## 1. Executive Summary

Signet is a local memory daemon that sits underneath eleven coding harnesses — Claude Code, Codex, OpenCode, OpenClaw, Kimi Code, Hermes Agent, Pi, Oh My Pi, Gemini CLI, ForgeCode and Muse Code. It captures their transcripts into one SQLite store, derives a semantic entity graph from that store in background passes it calls *dreaming*, and serves recall back through MCP tools and session hooks. It also syncs the identity files those harnesses read (AGENTS.md, SOUL.md, USER.md, MEMORY.md) and keeps a separate encrypted secret store.

**The memory is its own, and the best part of it is a citation gate.** A dreaming pass may not write a claim without citing a quote, and `citeEvidence` resolves that quote against the immutable episodic store with `record.content.includes(requested.quote)` (`platform/daemon/src/pipeline/dreaming-operations.ts:118`). `validateRequestBeforeWrites` rejects the whole batch before any write when one citation does not resolve (`:768`, called at `:1022`). The lookup is scoped by `agent_id`, so a citation to another agent's evidence fails as a scope mismatch, and the text it compares against is the credential-redacted render the model was shown (`pipeline/dreaming-evidence.ts:361`). Two structural operations, `merge_aspects` and `rename_aspect`, apply with a reason and no quote; they reshape aspects and never write a claim value (`dreaming-operations.ts:409-431`).

**Two layers that deliberately do not merge.** An episodic row is primary evidence and is never edited by the pipeline; the semantic graph is derived and can be rebuilt. The MCP `memory_store` description tells the model so: a save is *"immutable episodic evidence"* and a structured payload *"is not applied to the graph from this tool"* (`platform/daemon/src/mcp/tools.ts:642`). Deleting an imported source purges the claim projections derived from it (`semantic-memory-projection.ts:3-59`). Re-indexing an edited source keeps its Dreaming claims and queues each one whose cited quote vanished for the next pass to re-check (`source-claim-review.ts:106-117`).

**Credentials are redacted on the way out, and nothing is withheld.** A single detector in `platform/core/src/credential-detection.ts` finds private keys, provider keys, JWTs, bearer tokens and secret-named assignments, and every prompt- and agent-facing projection passes through `redactCredentials` (`:80`). That covers recall, hooks, MEMORY.md, identity sync, MCP tools and Dreaming evidence. Stored memories and transcripts keep the raw text. The project's own specification lists classifying content as hostile or injected as a non-goal, after measuring its earlier heuristic ledger blocking 63 benign sessions out of 2,377.

**The weakest point is the published number.** The README badge claims 97.6% LongMemEval answer accuracy. The repository's own committed run ledger holds eleven 50-question runs scoring 34 to 45 correct, and the commit that removed ranking rules it calls tuned to LongMemEval questions left the headline in place. The mutation history is the second gap: it is purged after 180 days, so "why does the system believe this" has a horizon.

## 2. Mental Model

A memory is first a piece of **episodic evidence**: text an agent, a hook, a plugin or an importer handed over, stored with a content hash, an owning `agent_id`, a `visibility`, and optionally a canonical structured payload kept verbatim in `evidence_meta`. It is immediately retrievable and it is never rewritten by the pipeline. `memory_kind` labels it `episodic` by exclusion. Anything whose `source_type` is not one of the daemon's own derived outputs — `extract`, `aggregate-recall`, `session_end`, `checkpoint`, `dreaming` (`platform/core/src/memory-provenance.ts:1-7`) — is evidence.

Belief is a second layer built from the first. A dreaming pass reads episodic sources it has not consumed and emits operations from a closed vocabulary: entity, aspect, claim-value and link creation, claim setting and supersession, merges, renames, archives, `flag` and `decline_attention`. Claim operations must cite a verbatim quote; hygiene operations must cite an attention-flag id, and a flag is one-use. A claim value may carry `occurred_start`, `occurred_end`, `valid_from`, `valid_until` and `time_precision`, and a claim whose valid time is older than the active one for its slot is inserted already `superseded` (`ontology-proposals.ts:1356`). Beside that sits `epistemic_assertions`, recording *who said what, when*, and `ontology_contradictions`, which stores two competing claim values side by side with both provenance snapshots rather than picking a winner.

Death is three different things. An episodic row is soft-deleted (`is_deleted = 1`), superseded (`superseded_by`), or marked `stale_at`; one predicate excludes all three from delivery. A claim value is archived or superseded. A *source* can be purged, which deletes its derived claim projections. Nothing keyed on the rejected text stops it returning. The live uniqueness index is `WHERE content_hash IS NOT NULL AND is_deleted = 0` (`platform/core/src/migrations/080-document-scope-columns.ts:96-104`) and the dedup lookups filter `is_deleted = 0` (`platform/daemon/src/routes/memory-routes.ts:460`, `:481`). A sentence that was forgotten is accepted as a new memory the next time it is said, and the next dreaming pass may cite it again.

Control is hybrid and the split is explicit: the agent writes evidence and reads recall, the daemon derives belief, and a person may adjudicate the subset of graph operations the dreaming model itself marked `review_required` — which is also why no review mark follows from it.

## 3. Architecture

**One daemon, one database, mostly one owner.** `platform/daemon` is a Bun HTTP server on Hono with routes split across `routes/` (memory, ontology, hooks, sources, transcript import, inference, marketplace, secrets, board, telemetry). Writes go through a db-owner protocol with read, write, maintenance and verify lanes, absolute deadlines and a 10,000-unit work budget, so long reads cannot starve the event loop. The migration is incomplete and tracked: 146 call sites carry a `LEGACY_SYNC_DB_ACCESS` marker, ratcheted down by `scripts/legacy-sync-db-baseline.json`, and the `event-loop-contract.yml` workflow guards the ratchet. `platform/core` owns the schema: 171 migrations, an integrity audit table, and a `vec0` virtual table created inside a `try` so the store degrades to lexical-only when the sqlite-vec extension is absent (`platform/core/src/migrations/001-baseline.ts:84-90`).

**Embeddings and reranking are local by default.** The `native` provider loads `@huggingface/transformers` with `nomic-embed-text-v1.5` (`memory-config.ts:335`, `:385`); `ollama`, `llama-cpp`, `openai` and `none` are the alternatives. Reranking defaults to a local ONNX cross-encoder, `mixedbread-ai/mxbai-rerank-xsmall-v1` (`memory-config.ts:161`). `platform/native` is a napi-rs crate (`knn.rs`, `search.rs`, `vector.rs`, `normalization.rs`, `tokenizer.rs`) for the scoring hot path and the cross-encoder's tokenizer.

**Dreaming needs a model, and it may be one you already run.** `inference-provider-factory.ts` offers `anthropic`, `openrouter`, `ollama`, `llama-cpp`, `openai-compatible` and `acpx`. The last drives an existing agent — Claude Code, Codex, OpenCode or Kimi — over the Agent Client Protocol, so the dreaming pass can be executed by the coding agent the user already has rather than by a separate key.

### Deployment and ergonomics

A single installed binary plus a background daemon (launchd on macOS), one SQLite file, and a workspace directory holding the identity Markdown. A Docker image is published to ghcr, and its entrypoint writes `auth.mode: team` on first run (`deploy/docker/entrypoint.sh:9-13`). It runs fully local and offline: local embeddings, local FTS5, a local cross-encoder, and a local LLM through Ollama or llama.cpp for dreaming. Without any model, capture, recall and scoping still work; what stops is the semantic graph. No API key is required to store anything.

Usage telemetry to PostHog is off until the user turns it on (`memory-config.ts:210`, `platform/core/src/telemetry-consent.ts:4-9`); the npm `postinstall` sends one anonymous install count, which `SIGNET_TELEMETRY_OPTOUT` suppresses. The store is ordinary SQLite and repairable by hand; `repair-actions.ts` (3,292 lines) and a database-integrity worker exist for when it is not. The surface is large for an operator: a daemon, a dashboard, a tray app, a desktop Electron build, a browser extension, and eleven harness connectors.

## 6. Retrieval Mechanics

Lexical and vector hits are fused by reciprocal rank with k = 60 (`platform/daemon/src/recall-rank-fusion.ts:1`, applied at `memory-search.ts:2470`), after `rankPositions` drops rows below `min_score` on their raw scores. `top_k` defaults to 20 and `min_score` to 0.1 in code, or 0.3 where a configuration still carries the retired `search.alpha` and in the setup template (`memory-config.ts:444`). Hint, temporal, traversal and structured-evidence candidates enter through their own branches, and `selectPrimaryCandidates` reserves room for directly anchored hits inside the traversal budget. Graph traversal degrades explicitly: a timeout or failure sets a `degradation` of `graph_traversal_timeout` or `graph_traversal_failed` in the response meta (`memory-search.ts:1927-1947`, `:2056-2064`), and lexical truncation reports `fts_incomplete`.

**Two filters run before ranking.** The lifecycle predicate, `currentMemorySql`, is written once and called at eighteen sites outside tests: `AND m.is_deleted = 0 AND m.superseded_by IS NULL AND m.stale_at IS NULL` (`memory-search-filters.ts:141-142`). The scope clause is appended whenever an agent is known. Every result then passes through `redactCredentials` before it is returned. Nothing is dropped for its content.

**Recall is deduped per session.** `applyRecallDedupe` suppresses what this session already saw unless `includeRecalled` is set, in which case repeats come back marked `already_recalled`, and records the claim in `session_recall_events` with a context epoch that a session clear advances (`session-recall-dedupe.ts:220`, `:268`). A recall's result therefore depends on the session's history, not only on the query, and the dedupe fails open on error (`:235-242`).

**The ranking rules tuned to the benchmark are gone.** Commit 066653488 (5 October 2026) removed keyword expansions for baking and TV queries, a hand-written structured-path thesaurus with per-word weights, an anchor boost only those words could trigger, an advice-intent boost, a billing-path bonus, a ×1.6 boost for `## Preferences` rows, and transcript terms matching LongMemEval's assistant phrasing. Its message calls them *"rules written for specific benchmark questions"*, mostly from an April commit, and reports an unchanged offline replay on its 50-question sample.

**Failure modes.** Traversal can return candidates whose only link to the query is graph adjacency, which is why they are dampened. Access counts are bumped for what is returned rather than for what is read. The `visibility = 'archived'` predicate is centralised in `buildAgentScopeClause` for recall and the read routes and hand-written in seven other files, including the Dreaming evidence readers and the MEMORY.md head owner.

## 7. Write Mechanics

A `remember` is **synchronous and cheap**: validation, a content hash, a dedup lookup, one insert, optional temporal edges, and embedding queued to a worker. There is no LLM on the write path. A memory is retrievable by lexical search as soon as the call returns and by vector search once the embedding worker reaches it; `embedding-coverage.ts`, `embedding-health.ts` and the embedding-repair checkpoints of migrations 156 and 157 exist to measure and close that gap.

**Consolidation is a separate, budgeted pass.** The dreaming worker wakes every 5 minutes, checks whether there is unconsumed evidence or queued attention, and runs one bounded pass over the scopes that have work. It does not re-read the whole store: `dreaming_evidence_consumption` records a per-source delivered offset, and `dreaming_evidence_exclusions` holds sources it deliberately skipped with a `failure_class` from `incomplete_transcript | source_projection | scope_mismatch | quote_mismatch | unknown`, a retry count and a requeue timestamp. A claim whose text carries a relative time, or an ISO date with no timing field, is refused per operation. The token bill scales with the day's activity, except for hygiene passes over the attention queue, whose cost follows graph size.

**Correction is explicit and logged.** `POST /api/memory/forget` defaults to `mode: preview`, so the destructive call is the second one. `txSupersedeMemory` refuses a self-supersede and refuses a target in a different agent, project, scope or visibility (`transactions.ts:685-694`). Every one of these writes a `memory_history` row with an actor. Mutations can be frozen globally by a `pipelineV2.mutationsFrozen` kill switch that returns 503 on each mutation route.

**On the read path**, session start returns a short invariant banner and a separate dynamic context, and a second start for the same session returns a minimal stub rather than re-injecting (`hooks.ts:670-695`). Keeping the invariant text in one block ahead of the variable text is the shape that preserves a provider's prompt-prefix cache. Identity files are budgeted per file — 12,000 characters for AGENTS.md, 10,000 for MEMORY.md under the `openclaw` preset — and `applyTokenBudget` truncates the assembled injection.

**Nothing filters hostile input, at write time or at read time.** The evidence is stored as received, and the only transform on the way out is credential redaction. The consequence is in section 9.

## 8. Agent Integration

The MCP server registers 62 tools unconditionally (`platform/daemon/src/mcp/tools.ts:400-2330`). They group as memory (`memory_search`, `memory_store`, `memory_get`, `memory_list`, `memory_modify`, `memory_forget`, `memory_feedback`), recall and sources (`signet_recall`, `signet_source_search`, `signet_session_search`, `signet_save_note`), knowledge (`knowledge_expand`, `knowledge_tree`, `knowledge_list_claims`, `signet_explain_claim`, `knowledge_hygiene_report`, `apply_ontology_ops`), entities, cross-agent messaging and peer context (`agent_peers`, `agent_message_send`, `agent_message_inbox`, `agent_message_ack`, `agent_message_retry`, `agent_context_update`, `agent_session_inspect`), a message board (`board_list`, `board_read`, `board_post`, `board_update`), secrets (`secret_list`, `secret_exec`, `secret_exec_status`), and a code-graph family gated at call time.

**The model has a lot of agency over evidence and less over belief than it first appears.** It can store, modify and forget episodic rows freely. It can write a claim only through `apply_ontology_ops`, which enforces the citation gate, and it chooses per operation whether a cited claim lands in the review queue or applies at once, because the queue is entered only when the model sets `risk` to `review_required`.

**The session-start injection has a budget, and the delivery record is written after delivery rather than before it.** What the hook puts in front of the model is bounded by three limits rather than by the recall's own result cap — `sessionContinuityMaxEntries` (15), `sessionContinuityMaxTokens` (3,000) and `sessionContinuityEntryMaxTokens` (250), each configurable and clamped on read (`platform/daemon/src/hooks-config.ts:6-8`, `hooks.ts:987-994`). Three details make it more than a `slice`.

Predicted context is concatenated ahead of the recalled pool (`hooks.ts:965-967`), so a full pool cannot push the prediction feature out of the section invisibly, which is what a single budget over a merged list does to whichever source sorts last. If the rendered section does not survive the outer `maxInjectTokens` cap whole, it is re-rendered from an empty list rather than emitted in part (`:1215-1218`). And the per-session dedupe is split across that boundary: candidates are read without claiming, and `claimRecallItemsAsync` runs only on the memories in the final section, re-rendering if a concurrent request claimed one in between (`:1222-1241`). A memory is marked as already shown only once it was shown, so a truncated injection does not burn a row for the rest of the session.

The hook then logs `memoryCandidateCount`, `memoryCount`, `memoryOmittedCount`, `memoryClaimSuppressedCount`, `memoryTruncatedCount` and `memorySectionTokens` together (`hooks.ts:1245-1255`), so the gap between what recall found and what the model saw is recoverable from the daemon's log. It is not a field in the response, so the agent consuming the injection cannot see it.

**Agents can read each other, within the roster.** `agent_session_inspect` returns another session's transcript tail, capped at 5 messages and 4,000 characters, credential-redacted, and allowed when the target sits inside the viewer's roster audience (`cross-agent-inspect.ts:7-11`, `:265-269`). The board of migration 171 reuses the same read policy for visibility (`board.ts:202-209`) and pushes activity into hook notifications. Both inherit the recall path's binding: in `local` auth mode the viewer is whichever agent the request names.

**Injection is by hook where a harness has them and by plugin where it does not.** Claude Code, Kimi Code, ForgeCode and Muse Code get hooks plus MCP; OpenCode, OpenClaw and Codex get native plugins; Hermes gets a memory-provider plugin; Pi and Oh My Pi get extensions; Gemini CLI gets MCP plus GEMINI.md sync. `libs/connector-base` and `libs/sdk` are the shared surface, and `integrations/openclaw/memory-adapter/src/index.ts` (2,193 lines, with a 2,438-line test file beside it) is the most complete example of adapting the daemon to a foreign memory interface. `signet sync` is local: it re-registers connectors and tightens permissions on key-bearing files, and sends nothing anywhere.

## 9. Reliability, Safety, and Trust

**Secret storage is built well.** Values live in `<workspace>/.secrets/secrets.enc`, mode `0600` in a `0700` directory, each encrypted individually with libsodium `crypto_secretbox` and a random nonce (`platform/core/src/secrets.ts:438-447`). The 256-bit master key is generated with `randomBytes(32)` (`:386`) and stored in the OS keychain under service `ai.signet.secrets` with a per-workspace account (`secrets-keyring.ts:51`, `:73-75`). Where the host has no keychain the store falls back to a key derived from the machine id (`getLegacyMasterKey`, `secrets.ts:280-286`), says so with a `.degraded-warning` marker and reports `status: "degraded"`; a host whose keychain is merely unavailable refuses writes instead (`:399-404`). There is no secrets table in SQLite and no API, CLI or MCP verb that returns a value: `GET /api/secrets` returns names, and the only way to use one is `secret_exec`.

**`secret_exec` keeps values out of argv and out of the shell.** It resolves values into a child process's `env`, never argv, and rejects shell metacharacters (`secrets.ts:929-936`, `:998`). Output passes a streaming redactor before it is returned to the caller (`:966-986`), and the resolved map is blanked on exit.

**Credentials are redacted on output and stored raw.** The detector in `platform/core/src/credential-detection.ts` finds PEM private keys, AWS, GitHub, OpenAI, Anthropic, Stripe, Slack, Google, GitLab and npm key shapes, JWTs, bearer tokens, and secret-named assignments whose value has a digit (`:3`, `:26-49`). `redactCredentials` replaces each span with `[redacted credential]` on recall, hooks, MEMORY.md, identity sync, MCP tools, Dreaming evidence and peer inspection. Checkpoint digests are redacted before they are stored (`session-checkpoints.ts:67`). Remembered memories, captured transcripts and embedding inputs are not, so with the `openai` embedding provider a stored credential is sent to the embedding API (`memory-routes.ts:1670`). The git-sync route pushes allowlisted workspace files to the user's own remote with no credential scan; `.secrets` and the database are on its explicit deny list (`platform/core/src/gitignore.ts:9`, `:72-73`).

**There is no prompt-injection defence at the memory layer, by stated design.** The project's specification lists classifying content as hostile, injected or unsafe as a non-goal, and nothing is withheld for content. The MCP `memory_store` description tells the model that *"only clean content is eligible for ordinary recall/search and Dreaming"* (`mcp/tools.ts:642`), which describes a filter the code does not have.

**Scope holds on the read paths and is not bound to a caller.** `buildAgentScopeClause` is real SQL on every `hybridRecall` arm and every memory read route, and the tests for it cannot pass vacuously. But `shouldEnforceScope` returns false when `authMode === 'local'`, which is the default (`platform/daemon/src/auth/config.ts:29`), so `resolveScopedAgentId` accepts whatever agent id the request names, and `agentId=all` lists every agent's memories. On a single-user machine that is the correct trade; in `team` or `hybrid` mode, which the Docker image starts in, claims bind it. One reader does not apply the clause on the memory row: session-start traversal hydration selects memories by id under the lifecycle predicate alone and relies on the ids having come from the agent's own entities (`memory-candidates.ts:119-170`).

**Withheld marks, stated once.**

`audit_log` — no. `memory_history` is appended inside `txModifyMemory`, `txForgetMemory`, `txSupersedeMemory` and `txRecoverMemory` with an actor and the old and new content, and no production statement updates a row. Two production paths delete them. The retention worker drops every history row older than 180 days on its 6-hourly sweep, with no setting that reaches it (`pipeline/retention-worker.ts:53`, `:312`). Purging an agent deletes every prior history row of its memories and leaves one content-free `purged` row each (`agent-removal.ts:23`, `:160`, `:166`), which a committed test asserts. A time-based prune is the case that fails the mark under [memini](../memini/), and "why does the system believe this" has a 180-day horizon here.

`tombstone` — no. The repository has a table called `memory_artifact_tombstones` and a route called `/tombstone`, and neither is the mechanism. The table is keyed `(agent_id, session_token)` with `removed_paths`, a record of what the MEMORY.md rolling window dropped so a privacy removal survives re-index; the route calls `txForgetMemory` with `force: true`, a soft delete. Nothing is keyed on the rejected *value*: the unique index excludes deleted rows and the dedup lookups filter `is_deleted = 0`. The retention worker copies a hard-deleted row, hash included, into `memories_cold` (`retention-worker.ts:228`), and only a repair statistics route reads that table. A user who says "forget that" and then discusses the same fact again gets it stored, and a later dreaming pass may cite the new row and re-assert the claim. The nearest value-keyed check, `existingReviewProposalId` (`pipeline/dreaming-operations.ts:824-843`), dedupes a re-proposal only when payload and evidence JSON are identical, and only on the review path.

`trust_state` — no. `entity_attributes.status` is `active | superseded | archived | deleted`, a free-text column with no CHECK constraint, and every graph read filters `status = 'active'`. `epistemic_assertions.status` is `active | archived | superseded`, lifecycle rather than belief, and its `predicate` enum types the speech act rather than the system's stance. An edited source raises a `contested_claim` attention row for the next dreaming pass and leaves the claim `active` (`source-claim-review.ts:83-117`). No field says *recorded but not believed*, and nothing on the recall path reads one.

**The ontology proposal queue fails `human_review` at both ends.** The queue itself is well built: a `review_required` operation is written to `ontology_proposals` with `status='pending'`, its payload, confidence, rationale, risk and evidence, and a committed test asserts that rejecting a pending proposal mutates no graph state (`ontology-proposals.test.ts:641`). What enters it is the model's choice. `risk` is a bare `z.string().nullable().optional()` on the operation contract (`pipeline/dreaming-operation-contract.ts:153`), `reviewOnly` is computed from `operation.risk === "review_required"` (`pipeline/dreaming-operations.ts:1095`), and the instruction to emit that value lives in the dreaming prompt (`pipeline/dreaming.ts:989`, `:1109`). The one deterministic route in runs the other way: a merge whose sources are pinned or type-mismatched is `blocked`, and `force` *downgrades* it to `review_required` (`ontology-proposals.ts:2981`).

What leaves the queue is an unverified name. `POST /api/ontology/proposals/:id/apply` and `/reject` set `applied_by`/`rejected_by` from `readString(body, "actor") ?? c.req.header("x-signet-actor") ?? "operator"` (`routes/ontology-routes.ts:870`, `:888`), so the recorded approver is whatever the caller typed, defaulting to the word *operator*; that same name is carried onto the claim memory's `who` and history rows. A queue the producer fills by choosing a string and empties by supplying another is a surface a person may use, not a gate they hold.

**Declared and unwired: the memory review queue.** `GET /api/memory/review-queue` (`routes/memory-routes.ts:1178-1200`) selects `memory_history` rows `WHERE h.event IN ('DEDUP', 'REVIEW_NEEDED', 'BLOCKED_DESTRUCTIVE')`. No production code writes any of the three: producers write `updated`, `deleted`, `superseded`, `recovered`, `merged`, `rederived`, `none`, `archived` and `purged`. The one test that calls the route plants a `REVIEW_NEEDED` row by hand to prove its agent scope (`routes/memory-routes-read-scope.test.ts:259`, `:343`). Neither queue carries a review mark, for different reasons: this one has no producer, and the ontology queue has a producer and a resolver the model can be.

## 10. Tests, Evals, and Benchmarks

600 `*.test.ts` files holding 195,230 lines and about 6,450 cases, with 20 `.test.tsx` and 9 `.test.mjs` files beside them; most of the cases are in the daemon package. I ran none of it.

**CI runs the whole suite.** `.github/workflows/pr-baseline.yml:58-59` runs `bun run test` on every pull request and every push to main, which is `test:workspace` (`package.json:67-68`): a build and then `bun test` over every workspace through a hermetic runner. It covers 619 test files out of 629, plus 2 through the docs package's search test; seven agent-coordination evals and one benchmarking-skill test sit outside it. Every test file the marks rest on runs there.

**The marks rest on tests that cannot pass vacuously.** `memory-search.test.ts:2388-2425` writes the identical string `"agent-isolation-marker recall content"` under `agent-a` and `agent-b`, recalls as `agent-a`, asserts `toEqual(["mem-agent-a"])`, and then asserts the access counters are exactly `{mem-agent-a: 1, mem-agent-b: 0}` — the excluded row was not merely filtered from the output, it was never read. `memory-candidates.test.ts:96-108` asks `fetchTraversalCandidates` for five ids, asserts `toHaveLength(3)`, names each survivor's score and asserts `byId.has("memory-deleted")` and `byId.has("memory-superseded")` are both false. `hooks-recall.test.ts:903-908` pairs a `not.toContain` with a positive `toContain` and an explicit `expect(body.meta?.noHits).toBeFalse()`. `routes/memory-routes-read-scope.test.ts` seeds an archived row beside two live ones (`:139`) and asserts recall returns exactly the live pair (`:446`). The archived row is excluded by implication: no assertion names it.

**Two nearby tests read better than they assert, and a reader picking evidence should skip them.** `memory-similar-lifecycle.test.ts:123-165` has four `not.toContain` lines for deleted, superseded, stale and aggregate rows under `expect(ids).toHaveLength(0)` at `:160`, with no positive control; the sibling case at `:212-230` is the one with teeth. `memory-search.test.ts:2277-2307` seeds a live control row but queries a marker that does not match it, so an empty result passes the soft-delete exclusion silently.

**Twelve tests report green having asserted nothing, and in CI they always do.** `synthesis-worker.test.ts` opens twelve of its fourteen cases with `if (!DB_AVAILABLE) { console.warn("SKIP: real DB not available"); return; }` — a pass, not a skip. `DB_AVAILABLE` looks for a database under the home directory, and the hermetic runner gives each run an empty `HOME`. `scripts/native-embedding-runtime-smoke.test.ts:285` is the counter-example: it throws *"native binary not found"* rather than returning green.

**The benchmark headline is not backed by the repository's own runs.** The README badge and headline say 97.6% LongMemEval answer accuracy (`README.md:13`, `:147`), repeated in four translated READMEs, the marketing site and `web/docs/src/content/docs/benchmarking.md:17-20`, which points at `docs/BENCHMARKING-PROGRESS.md`. That document opens *"This is a development progress log, not a publishable benchmark claim"* and its largest denominator is 12. A second ledger, `.agents/skills/benchmarking/results/ledger.jsonl`, records 24 runs. Eleven use a 50-question proportional sample of the 500, and they score 34 to 45 correct; the best is 45 correct out of 50 with a thinking answer model. No run in either file reaches 97.6%.

The figure first appears on 21 April 2026, two days after the commit that 066653488 names as the main source of the benchmark-specific ranking rules it removed. No per-question result is committed: `memorybench/.gitignore:5` ignores `/data/`, the dataset is fetched from HuggingFace at run time (`memorybench/src/benchmarks/longmemeval/index.ts:15`, `:111`), and the RunPod run kit copies its evidence to a directory outside the repository. The harness computes accuracy, Hit@K, MRR and NDCG and gates on none of them.

**No paper.** A case-sensitive search over `README.md`, `docs/` and `web/docs/` for `arxiv|bibtex|@article|@misc|CITATION|doi.org` finds a research-tracking reference to [arxiv:2601.07372](https://arxiv.org/abs/2601.07372) in `docs/specs/dependencies.yaml` and `docs/specs/INDEX.md` as an input to a predictor design, and nothing else; there is no `CITATION.cff`.

## 11. For Your Own Build

### Steal

- **Validate a citation against the store, before the batch writes.** Have the consolidation model return `{quote, source_ref}` per operation, resolve the ref in the same scope the write targets, check the quote is a verbatim substring of the text the model was shown, and reject the whole batch on the first failure. Then record *why* it failed — `quote_mismatch`, `scope_mismatch`, `source_projection`, `incomplete_transcript` — so the failures are a queue you can retry rather than a log line.
- **Keep evidence immutable and make belief a projection.** Label rows as primary or derived, never let the pipeline edit a primary row, and make source deletion reach the derived rows. When a source is edited instead of deleted, keep the derived claims and queue the ones whose quote no longer appears for re-checking.
- **Order claims by valid time, and test that write order cannot win.** A late-arriving older fact should land superseded; one test that inserts the newer fact first and the older one second pins it.
- **Store contradictions whole instead of resolving them.** Both contents, both confidences, both provenance snapshots, a detector name and a resolution reason, with the attribute ids as soft links so the observation outlives the claim it was about.
- **Redact credentials at one choke point on the way out.** One detector, one function, called on every projection that reaches a prompt or an agent; the stored evidence stays inspectable.
- **Make a destructive bulk operation take `mode: preview | execute`.** Two calls, the first of which shows exactly which rows match.

### Avoid

- **Publishing a headline your own ledger does not reach.** A badge is a claim; a committed per-question output file is evidence. When the committed runs top out at 90%, the 97.6% figure needs a source or a retraction.
- **A consumer whose producer was never written.** Three event names in one `IN` clause and nowhere else in production is an endpoint that returns empty forever; a test that plants its own rows proves the route, not the queue.
- **Letting a suite report PASS when its dependency is absent.** An early `return` inside a test is a pass, and a hermetic CI runner makes the dependency absent every time. Use the runner's skip, or throw.
- **Redacting at delivery and calling the store clean.** Transcripts, memories and embedding inputs hold the raw credential, and anything that reads the database or the embedding provider's logs sees it.

### Fit

This is the heaviest system a single developer can reasonably run. If you work across three or four agents and the fragmentation of context between them is the actual pain, Signet is aimed at that, and the eleven-harness plumbing is most of what you are buying. The citation gate and the immutable evidence layer mean the derived graph is disposable, which is the property that makes a background consolidation pass safe to let run unattended. If you use one harness on one project, this is several services, a 171-migration schema and a dreaming model's token bill to solve a problem a much smaller store would solve. Walk away if you need a memory layer you can fully audit in an afternoon, a mutation history that outlives six months, or transcripts that never sit unredacted in a local database.
