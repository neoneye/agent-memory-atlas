On this page

1. Executive Summary

EGC (Extended Global Context) is a local runtime for AI coding tools. egc install registers a memory server and a command guard in every coding tool it detects, writes a memory protocol into their instruction files, and installs hooks. The memory server keeps project state as an encrypted Markdown document per git branch, and keeps decisions and lessons as plaintext SQLite rows that every project's searches return.

Four faculties ship together:

  • Memory — the egc-memory MCP server and a set of lifecycle hooks
  • Guardian — a command and write guard
  • Token Crusher — an output filter
  • Session Mesh — a bus that lets open sessions see and message each other

The repository also ships an optional library of skills, agents and commands.

The README promises that memory "lives in ~/.egc, encrypted with AES-256-GCM, kept per project and branch". State documents meet that at rest: a project's context, decisions, things not to repeat, preferences and next steps are encrypted per branch, with an HMAC sidecar and a read that falls back to main. Three things qualify "per project". A document's key is the last two segments of the project path, so ~/a/acme/api and ~/b/acme/api share one. Every update_state mirrors part of the document in plaintext into the project's instruction files. And the transcript miner and team sync write into it without the injection scanner the MCP tools apply.

Decisions and lessons live in one plaintext SQLite database for the whole machine. Each row records the project it was written from, through migrations whose comments say "for per-project scoping", and no read applies it. query_history, search_history and lesson_recall return rows from every project.

One mark, negative_eval: committed cases assert that another project's working memory, an expired entry and an overwritten decision stay out of the results (section 10).

2. Mental Model

An agent sees one memory server with three kinds of memory:

  • Project state — the document get_state returns at session start and update_state merges into at the end, per branch. A user-wide global document is appended to every project's read.
  • History — decisions stored one at a time and searched with BM25, and lessons with a confidence that rises when reinforced and decays when unused.
  • Working memory — short-lived keys per project with a TTL, 24 hours by default and seven days at most.

Hooks write into the state document without the agent asking. At session end and before compaction a model mines the transcript into decisions, things to avoid, preferences and next steps. A prompt classified as "remember" is appended verbatim to the active decisions. Nothing in the state document has a status: an entry is in the document or it is not, and only a merge or a consolidation removes one.

Lessons have one lifecycle field. archived is set by the decay sweep when confidence falls below 0.2, cleared by reinforcement, and every recall excludes it. It is derived from the confidence float rather than set by a judgement, so it is a retention rule and not a trust state.

Deployment and ergonomics

  • Install: npm install -g @egchq/egc && egc install; the installer writes MCP configuration, hooks and instruction files into each detected tool.
  • Storage: everything under ~/.egc, with an encryption key and an integrity key at mode 0600.
  • Two databases. The memory server opens ~/.egc/memory/state.db and the CLI opens ~/.egc/egc/state.db; a comment calls this a known divergence (index.ts:392-396) and doctor checks both locations.
  • Side effects in user repositories. Before mirroring state into a project, the server writes a git clean filter into that repository's .git/config and .git/info/attributes. It withholds the mirror when the filter cannot be armed (propagate.ts:47-71, scripts/lib/memory-filters.js).
  • Model calls: none in the memory server. The transcript miner calls a provider only when a key is set, and skips otherwise.
  • Hand-repairable: the SQLite store yes; the state documents through the server, egc export (read-only) or egc consolidate, since they are encrypted.

5. Memory Data Model

State documents are Markdown with a header naming the project, encrypted as a five-byte EGC1: magic, a random IV, the GCM tag and the ciphertext, and paired with an HMAC-SHA256 sidecar. The path is ~/.egc/state/<slug>/<branch key>.md, or detached--<commit>.md for a detached HEAD. update_state accepts scope: global for a machine-wide document that every project's read appends.

The slug is lossy. projectSlug joins the last two path segments and replaces anything outside [a-zA-Z0-9-_] with _ (branch-state.ts:17-20). Branch names get a hash suffix because "sanitization alone is not injective" (:26-27); project paths get none. Two checkouts at ~/work/acme/api and ~/old/acme/api, or my.app and my_app under one parent, read and write one document. The test file pins the two-segment form and has no collision case.

Decisions (index.ts:264, :332): id, context, decision, timestamp, project_path. Nothing in production updates or deletes them.

Lessons (index.ts:291-301, :325, :354): id, content, context, confidence (0.7 by default), last_reinforced, last_recalled, created_at, tags, archived, project_path, author. Reinforcing adds 0.15 and unarchives. The sweep removes 0.05 per week after 30 days without recall and archives below 0.2 (:651-654, :686-697). Migration 9's comment says it adds author to "lessons and decisions"; it alters lessons only (:351-354).

The producer test on project_path. Both history tables gained the column in migrations 6 and 7 (index.ts:322-333). store_decision and lesson_save write it from the server's working directory (:1910, :1162). Across the server, the column is read only by the working-memory and session-bus queries. No decision or lesson read has a WHERE project_path, so scope_enforced is withheld.

The memory server has no validity axis, no rejection record and no mutation log, so bitemporal, tombstone and audit_log are withheld. The AUDIT level of its rotating operational log has no caller, and the Guardian's ~/.egc/audit.log records denied commands, not memory writes.

6. Retrieval Mechanics

Session start has two readers of the same file. The MCP get_state decrypts it. The egc-memory-load hook, registered at SessionStart, reads it with fs.readFileSync(path, 'utf8') (egc-memory-load.js:39) and places the result in promptForAssistant. It decrypts the global appendix through state-crypto and the project document not at all, so the field carries the EGC1: header and ciphertext bytes. Its tests use plaintext fixtures (tests/lib/branch-state.test.js:62-65), a shape no production writer produces. session-context-loader.js reads the same file correctly, and says why: "encrypted content stays silent instead of leaking ciphertext".

Prior-session summaries are injected at session start by session-start.js. selectMatchingSession prefers a summary whose Worktree matches the working directory, then one whose Project name matches. Failing both it returns the most recent summary from any project (session-start.js:215-243). That summary is wrapped as "HISTORICAL REFERENCE ONLY" and injected.

Intent hooks inject sections of the decrypted state document on a resume or history prompt, clipped to 1,600 characters, without the scrub the mirror applies (prompt-intuition.js:105-116).

Decision search sanitises the query into an FTS5 match, ranks by BM25 and normalises scores to [0, 1] against the best hit (search.ts:169-195). Without FTS5 it matches every term by LIKE and scores each hit 1. query_history pages through all decisions by time.

Lesson recall matches FTS5 over content, context and tags, keeps rows with archived = 0 and confidence above the minimum, stamps last_recalled, and hands back any field that reads as an instruction as the blocked marker. The substring fallback does the same over the top rows by confidence.

Every project, every time. None of these three reads is given the project. An agent asking what was decided about authentication receives decisions from every repository on the machine, in BM25 order. The search result carries no field naming the project, since searchDecisions selects id, content, context, date and score. query_history returns the column and does not filter on it. Lessons are the same. The README's "what one agent learns, every agent knows" holds across tools, and also across projects, which the migrations were written to prevent.

7. Write Mechanics

Sanitisation on the MCP tools. sanitize.ts scans free text for prompt-override and command-injection patterns, mirroring the Guardian scanner. It applies to every free-text field of update_state, to store_decision, to working_memory_set, and to lesson_save. Lessons are checked field by field and with the fields read together, so a directive split across fields is caught (index.ts:1179-1190). The same check runs on every lesson read, so a row written by any other path comes back as data.

Unscanned writes to the state document. applyMinedMemory appends the miner's decisions, things to avoid, preferences and next steps through the hook library's own encrypt-and-write path (state-snapshot.js:150-172, :234-257). Neither it nor mineTranscript calls a scanner. Team sync merges a teammate's document after verifying its envelope and writes it without a scan or an HMAC sidecar (sync/TeamSync.ts:278-296). get_state returns the project document as stored. The mirror into instruction files is scrubbed again before writing (index.ts:1463-1474); the agent's own read is not.

Dedup. A lesson identical in content and context to a live one reinforces it instead of inserting. The miner skips a line the document holds verbatim.

Arbitration. SQLite writes go through one in-process queue; state merges in the server and in the hooks take the same .merge.lock file, so a hook's read-modify-write cannot drop a server merge.

Observations and patterns. Hooks record runtime events. compress_observations turns raw observations into typed summaries by rule. When they come from the CLI state database it stamps compressed_at and keeps the event. When they come from observations.jsonl it overwrites the raw line with the summary (compress.ts:337-343). detect_patterns counts repeated commands and error signatures.

Consolidation. egc consolidate, and the session context loader on a plaintext legacy file, layer dated entries by age after writing a backup (scripts/lib/state-consolidate.js). The active queue and the context section are never layered.

8. Agent Integration

  • 24 memory tools: project state, decisions, the session bus (announce, claim and release paths, peers, send, events, wait), working memory, lessons, patterns, compression, server health, and team init, sync and status.
  • Instruction files in each tool carry a memory protocol that routes "remember this decision" to update_state and describes store_decision as searchable history that get_state does not return (rules/common/memory.md:38-42).
  • Mirrors. Every update_state writes a block headed by a generated-data notice into up to twelve context files, each only where the file or its tool's directory exists: CLAUDE.md, AGENTS.md, GEMINI.md, Cursor and Windsurf rules, llms.txt and others (propagate.ts:453-474).
  • Session bus calls act as the server process's own session inside the project it joined, and refuse another session id or project. Memory calls are not bound that way: get_state, update_state and the working-memory tools accept any project_path outside hidden home directories and system roots (index.ts:540-578).
  • Team sync pushes and pulls through a git remote with a shared team key, merging only files that open as team envelopes for their path, and never deleting a local document.

9. Reliability, Safety, and Trust

The encrypted path is careful. Keys are read per call, so a changed home cannot pair one key with another directory's file (index.ts:438-453). An undecryptable file aborts a write rather than being overwritten; force renames it to a timestamped backup; HMAC mismatches warn without blocking; a link anywhere on a mirror or sync path is refused.

Encryption at rest covers the files under ~/.egc/state, not the memory. The same context, up to five decisions and up to five next steps are written in plaintext into the project's existing context files on every update. The clean filter keeps them out of commits, not off disk. Decisions and lessons sit unencrypted in one database every project reads.

Isolation between projects holds for working memory, partitions state documents by a lossy key, and is missing for history and for the session-start summary's fallback. On a machine with client and personal work in separate repositories, recall mixes them.

Injection. The scanner guards the MCP tools and the mirrors. A model-mined digest of a transcript that quoted a hostile page reaches the state document unscanned and returns through get_state verbatim.

Human review. The dashboard shows counts of decisions, lessons and patterns, replays and costs, and has no route that edits or removes memory. The CLI's commands over state documents are a read-only export and the consolidation, and none lists or edits decision or lesson rows. No memory waits in a state for a person, so human_review is withheld.

11. For Your Own Build

Steal

  • Branch-aware project state with a default-branch fallback and a per-commit file for a detached HEAD, so a new branch inherits context and a CI checkout cannot overwrite a shared file.
  • Encryption with explicit failure modes: abort on undecryptable, quarantine only when asked, warn on HMAC mismatch.
  • Scan on read as well as on write. presentLesson hands back any stored field that reads as an instruction as a marker, so rows written before the scanner, or by another path, arrive as data.

Avoid

  • A scope column written and never read. Add the predicate in the same change as the migration, with a test from a second project.
  • A partition key derived from a display name. Hash the full path, as the same file does for branch names.
  • A sanitizer applied per handler instead of at the write layer. Here the MCP tools are covered and the hook-side miner and the sync merge write the same document without it.
  • Two readers of one encrypted file that decode it separately. Route every reader through one function, and build test fixtures with the production writer.

Fit

EGC suits a developer who works in several AI coding tools at once and wants them to share project state and coordinate edits, and who values the guard and output filter as much as memory. For decisions and lessons that must stay within their project, for memory that must stay off disk in plaintext, or for checkouts that share a parent and directory name, the history tables need a predicate, the mirror needs to be optional, and the slug needs a hash first.

12. Open Questions

  • Should search_history, query_history and lesson_recall filter on project_path by default, with an explicit cross-project option?
  • Does any harness render promptForAssistant? The load and save hooks set it; nothing in the tree consumes it, so whether the ciphertext reaches a model depends on the host.
  • Should the session-start summary fall back across projects at all, or stop at a worktree or project-name match?
  • Will the SQLite store move under the same encryption as the state documents, and will the two state databases be merged?
