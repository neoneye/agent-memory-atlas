1. Executive Summary

OmniNode's knowledge base is a decision ledger kept as typed Markdown: every artifact's frontmatter is validated against a per-type schema, and a pull request cannot merge past eight validator checks and a test suite. What none of those checks covers is the rule the README leads with — that "a decision is not accepted, a pivot is not confirmed, and an experiment is not concluded until the evidence artifact exists and is referenced". The status field that rule governs is validated, printed in an index, and read by nothing else.

It is OmniNode's public architectural provenance record and the canonical home for its external documentation: ADRs, pivots, doctrine, architecture documents, plans and experiments, beside guides, reference pages and runbooks. It is in this atlas for the same reason Cambium and breadcrumbs are — the store is a working method rather than a runtime, and the method is the part worth reading.

The repository was renamed from OmniNode-ai/knowledge-base to OmniNode-ai/knowledge_base on 9 October 2026, and the old address redirects. The rename reached CLAUDE.md, the README badge, the reusable workflow and the sanitization allowlist, which exempts both spellings. pyproject.toml keeps name = "knowledge-base", and CI's drift-guard self-check passes --repo-name knowledge-base.

The schema is the good part. scripts/validate.py:145-252 declares one Pydantic model per artifact type, each pinning status to a Literal, with _discriminate choosing the model from type. An ADR is proposed, accepted, superseded, deprecated or rejected; a pivot is observed, emerging, accepted, historical or superseded and carries a separate confidence. extra="forbid" means an unknown key fails. --export-schema writes schemas/frontmatter.schema.json, and CI fails when the committed copy differs.

The evidence rule is where the gap is. The evidence artifact type was removed on 26 August 2026; the validator's own comment names OCC (onex_change_control) as "the sole evidence authority — this repository cites outcomes, it does not host receipts". The README rule asks for a reference, then, not a hosted file. At the pin 32 ADRs and 5 pivots are accepted. Eighteen carry an ## Evidence section, and it is prose describing what was observed. None links a receipt, a CI run or a pull request, and the other nineteen have no Evidence section. No check counts either.

The ledger's keys are sound. check_adr_id_uniqueness (scripts/validate.py:478-496) fails any two ADR files sharing an adr_id, with no exemption, and a test runs the whole validator over a fixture tree holding a duplicate. The one historic collision was resolved by renumbering: the later file is ADR-0052, opening with "Former id: ADR-0010".

2. Mental Model

A memory is a file with a type and a status. The type decides which fields are legal and which statuses exist; the status says whether the claim is held.

adr           proposed | accepted | superseded | deprecated | rejected   + adr_id, supersedes, superseded_by
pivot         observed | emerging | accepted | historical | superseded   + observed_date, confidence: low|medium|high
doctrine      draft | accepted | deprecated
architecture  draft | accepted | superseded | deprecated
plan          draft | active | completed | superseded
experiment    proposed | active | completed                             + hypothesis, outcome: confirmed|refuted|inconclusive|None
guide, reference, runbook   draft | current | stale | deprecated

Two of those deserve a second look. A pivot carries a confidence of low, medium or high beside its status, which is the separation this atlas argues for — how sure you are is not the same axis as whether the claim is current. And an experiment carries a hypothesis and an outcome that may be confirmed, refuted or inconclusive, a first-class refutation. experiments/ holds a README and a template and no experiment.

Correction is supersession, expressed in frontmatter rather than by editing the superseded text. ADR-0027 lists supersedes: [ADR-0026], ADR-0026 lists superseded_by: [ADR-0027] and carries status: superseded, and both files stay in the tree. That is the only pair in the corpus, and it is reciprocal by hand. Two architecture documents also carry status: superseded, and the architecture model has no field to say what replaced them.

The design records what was rejected as well as what was chosen. Every ADR carries an "Alternatives Considered" section with the reason each option was refused. ADR-0019's first reads "self-attestation defeats the gate; agents lie; an OCC receipt written by the party it certifies is not evidence". That is a rejected-value record kept in prose, keyed by nothing and consulted by nothing.

3. Architecture

There is no runtime. The repository is the system, and six Python scripts are the enforcement:

  • scripts/validate.py (695 lines) — the Pydantic models, the eight checks, --export-schema, --fix-indexes and --root.
  • scripts/generate_indexes.py (212) — rebuilds indexes/chronological.md, by-topic.md and by-type.md from frontmatter.
  • scripts/sanitization_patterns.py (92) — the shared pattern set: internal ticket references, internal IPs and hosts, private repository URLs and names, secrets-manager references, email addresses.
  • scripts/check_text_sanitization.py (118) — the same patterns over commit messages, PR titles and bodies, and a commit range, without the allowlist.
  • scripts/docs_drift_guard.py (250) — run by other OmniNode repositories through a reusable workflow; it reads migration-manifest.yaml from this repository's main and fails a product repository that re-grows a migrated document.
  • scripts/check_customer_guide_primary_path.py (169) — asserts a customer guide's primary path names onex cloud and contains no curl.

scripts/verify_clean_container_quickstart.sh is a manual container check of the product quickstart; no workflow calls it.

.github/workflows/ci.yml runs ruff, pytest, validate.py, the guide check, a schema-freshness diff and the drift-guard self-check in one job, and the PR-text scan in a second. .pre-commit-config.yaml wires the commit-message gate locally.

Deployment and ergonomics

uv and Python 3.12. Nothing is served, nothing is indexed, nothing runs on a schedule. For a team that already reviews by pull request this costs one CI job; for anything else there is nothing to deploy.

4. Essential Implementation Paths

The schema — validate.py:145-252: a base model with extra="forbid", one subclass per type pinning status, and a TypeAdapter over the discriminated union. validate_frontmatter (:387-413) rejects an unknown type before the union runs, with the valid set derived from the base model's Literal so the two cannot drift.

Registered locations — check_registered_locations (:332-359) walks the whole tree and fails any .md, .yaml or .yml file outside a declared section, generated directory, .github or the root allowlist. A file in a new place is an error, not a silent skip.

ADR id uniqueness — check_adr_id_uniqueness (:478-496) groups ADR files by adr_id and fails any group larger than one.

Cross-references — check_cross_references (:504-516) resolves every refs: entry against the tree and fails on a miss.

Index freshness — check_index_freshness (:548-574) regenerates the three indexes in memory and compares them to what is committed, so a stale index fails the build rather than misleading a reader.

Sanitization — check_sanitization (:529-540) scans artifacts, section READMEs and templates, indexes/, docs/, .github/ and the root charter files. scan_text honours a # sanitization-ok: marker there. The text gate calls it with the allowlist off, and its docstring says why: "text gates must not let an author self-exempt leaked content" (check_text_sanitization.py:28-29).

What has no path — the only reads of status outside the models are generate_indexes.py:168-169, which prints it. supersedes, superseded_by, confidence, hypothesis and outcome are read by nothing but the validator.

6. Retrieval Mechanics

The repository ships no query. Retrieval is opening one of three generated indexes or grepping the tree, and the README names the intended entry point in prose.

The freshness check means the indexes can be trusted to match the files. It also means the store has no way to answer the question its own status field makes askable — which accepted decisions are current — without a person reading every entry. A superseded ADR appears in indexes/by-type.md exactly like an accepted one, distinguished by the word after an em dash.

7. Write Mechanics

A write is a pull request, and the gate is CI. Nothing is extracted, summarized or consolidated; the only derived artifacts are the three indexes, regenerated by hand and verified in CI.

Deletion is not modelled. The correction path is supersession, which keeps the superseded artifact and marks it. Removing a claim that should never have been recorded is a different need, and the sanitization gate covers part of it by refusing the content at the boundary.

The fix for the ADR-0010 collision shows the write discipline at work. The later file was renumbered rather than either decision being edited; every reference was rewritten to ADR-0052; the renamed file carries a former-id line; and the exemption that had registered the collision was deleted in the same change.

8. Agent Integration

CLAUDE.md is the whole integration: the commands, the gates and the rules, ending with a comment that records when it was last reconciled with the code — "verified against scripts/, .pre-commit-config.yaml, and .github/workflows/ci.yml on the 2026-08-19 charter refresh". The habit is worth copying, and the stamp shows its limit: the file was edited on 26 and 31 August and on 9 and 15 October, and the stamp did not move.

The agent-facing content extends past the contract. ADR-0019 exists because an implementing agent wrote its own verification receipt: "agents lie, and self-attestation is not proof". The decision is that evidence comes only from an autogen tick or an independent verifier. That rule is recorded here as a decision, not implemented here as a check — the receipt gate it describes lives in OCC.

9. Reliability, Safety, and Trust

Every check fails the build, and the validator's checks have tests. Nothing here is advisory, which distinguishes it from most documentation repositories.

Two invariants the repository states are not checked.

  1. "A decision is not accepted… until the evidence artifact exists and is referenced." No accepted ADR or pivot links one, and no check counts. With evidence held in OCC, the missing thing is the reference, and a reference is a string the validator could require.
  2. Supersession is reciprocal. ADR-0026 and ADR-0027 point at each other. A future pair that does not would pass every check, leaving a superseded claim that reads as current. On architecture documents the status exists with no pointer field at all.

Both are cheap in a validator that parses every file into a typed model: a dictionary lookup for the back-link, and a required refs: or evidence entry on anything accepted.

Sanitization is the strongest safety property. It reaches artifacts, indexes, .github/, root files, commit messages and PR text. A comment at validate.py:117-126 records why .github/ joined the scan: a workflow comment named a private repository and the gate reported green over it.

docs_drift_guard.py comes closest to a rejected-value record in the tree: a manifest row keyed on a migrated document's path, checked against every later PR in the product repository. It governs documents across repositories, not claims.

10. Tests, Evals, and Benchmarks

tests/ holds 91 pytest functions in five files, and CI runs them before the validator. TestAdrIdUniqueness (tests/test_validate.py:216-284) covers distinct ids, a duplicate, a triple, a non-ADR type, the live tree, and a full validate.py --root run over a fixture holding a duplicate. Other classes cover the frontmatter union, recursive discovery, the registered-location walk, the naming shapes and the index generator. No test asserts anything about evidence references or supersession, because no check exists to test.

There is nothing to benchmark, and the repository claims no numbers. I ran nothing: the counts here come from reading the frontmatter of every artifact at the pin.

11. For Your Own Build

Steal

Generate the schema from the models and fail CI when the committed copy drifts. --export-schema plus a git diff --exit-code means the published contract cannot describe a validator that no longer exists.

Give each artifact type its own status vocabulary. A pivot that is emerging and an ADR that is proposed are different epistemic claims, and one shared enum would have flattened both.

Verify the index rather than trusting it. Regenerate in memory, compare to what is committed, fail on a difference.

Fail closed on location. A walk that errors on any content file outside a declared section removes the gate that reports green over the part of the tree it was never pointed at.

Deny the allowlist where nobody reviews. An escape hatch for reviewed artifacts that does not apply to commit messages is a considered boundary.

Resolve a key collision by renumbering with a former-id line, and delete the exemption in the same change.

Avoid

Stating an invariant in a README and enforcing the schema instead. The rule the project leads with is the one a reader cannot rely on.

A superseded status with no pointer. Two architecture documents say they were replaced and nothing says by what.

A dated reconciliation stamp that edits do not move. It reads as current while describing an older file.

Fit

Right for a team that wants its architectural reasoning inspectable and will pay for it in pull requests. The checks are a good floor and the type-per-status model is better than most.

Wrong as agent memory in the sense the rest of this atlas means it. Nothing retrieves, nothing scopes, nothing reads a status back, and no agent writes here without a pull request. Take the schema and the checks; the runtime is OmniIntelligence and OmniMemory, read separately.

12. Open Questions

Where the reference from an accepted ADR to its OCC receipt is meant to live. The README asks for one, pivots/README.md says an Evidence section "should cite these artifacts by reference", and no artifact's frontmatter has a field for it.

Which ADR supersedes the two superseded architecture documents, if any; the architecture model cannot say.

What happens to a claim that was wrong rather than superseded. The ADR enum has rejected, no artifact uses it, and the difference between deciding against something and deciding something untrue is not modelled.
