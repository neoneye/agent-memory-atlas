On this page

1. Executive Summary

Osiris is an event-sourced entity graph that agents use as shared memory, in which a fact's confidence is derived from how it was obtained and a lifecycle status keeps merged and retired objects out of every search route. Its write path is one actions layer that records identity and lifecycle changes as events. Its weak side is the distance between the stated rule and the housekeeping: the module header promises append-only tables, and a daily job deletes audit rows and redundant assertion rows.

The project describes itself as "a self-hosted memory and coordination graph for AI agents", one Postgres-backed service "reachable from any harness over the Model Context Protocol". Its tool surface coordinates a fleet of agents — mail, seats, threads, decisions, handoffs — over the same graph that holds what they learned.

Parsers declare how they knew. The evidence module opens with the defect:

"Before this module, every parser invented its own confidence number (0.4 → 0.99) with no shared meaning, so 'noise' was baked into the graph as fake-precise facts and nothing downstream could reason about why a node was believed."

Five classes a parser may declare each project a base confidence, and confidence is "a projection of the class, not a guess" (src/parsers/evidence.py:21-31). The sixth, CORROBORATED, "is never assigned by a parser — it is computed at read time when ≥2 independent sources agree". The crawl frontier computes it from distinct source ids (src/orchestrator/frontier.py:105-144). The agent's search does not: its grade weights carry a corroborated branch that no stored row reaches.

The status filters. objects.status is a projection of the object_events log, moved by merge, unmerge and set_status. Every route of _fn_search requires o.status = 'active', and the embedding backfill deletes the vectors of an object that left active (src/orchestrator/compositions.py:421-722, src/orchestrator/semantics.py:215-217). A merged object stays in the graph and does not come back through search.

One write path, with events. The actions layer calls itself "the only mutation path into the ontology", and every identity and lifecycle change appends an object_events row in the same transaction as the projection it moves. No production statement updates or deletes that table.

The rule and the housekeeping disagree. The header says "old rows are never mutated" and the README says every change "appends an event, never overwrites or deletes". A repeated observation moves the existing row's observed_at in place. A daily heartbeat deletes audit rows older than 90 days. A second deletes audit rows that repeat an assertion, superseded assertions identical to the row they replaced, and old layout assertions. The fold module argues its case — "nothing the graph knows is lost" — and the deletions do not pass through the actions layer.

Reflections are house-scoped; the rest is shared by design. Decisions, threads and canon are "fleet-readable; cross-repo recall is the product". A reflection is readable within its own house and by the operator on search, the provenance lens, select and the screen-focus tool, and committed tests assert that another house gets no hit. dossier and list_assertions do not apply that check, and the search function takes its reader from an argument a saved composition can set.

2. Mental Model

An object is a typed node with a canonical name; its type comes from a reviewed catalog. An assertion is one source's claim about one property, graded by an evidence class. A new claim from the same source supersedes that source's current row; claims from other sources stand beside it as a multi-source set.

A belief has two separate standings. The evidence class says how a claim was obtained; it ranks search hits and decides which crawl nodes may expand, and search withholds nothing by it. The lifecycle status says whether the object takes part at all: active, or merged, archived, retired, historical. Search returns only active objects.

The status moves only by event. merge_objects writes a merge event and sets merged; unmerge_objects writes an unmerge event and restores active, leaving the merge event and its same_as link "as witnesses of the era" (src/actions/core.py:709-753). set_status writes a status_change or archive event with a required justification before it updates the projection (:818-846). A mined object a re-mine no longer produces is archived, and reactivated when the source produces it again (src/ingest/mined.py:104-118).

Two signals label and do not withhold. A decision another decision supersedes is returned with a superseded flag naming its successor, and a refuted practice is returned with a refuted flag (compositions.py:536-560). The open-thread wall that orient renders does withhold: a thread with no self-declared assertion, either a question or older than a freshness window, goes into a counted echo pile instead of the list (compositions.py:3514).

Nothing an agent writes waits for anyone. The miner's guesses about forgotten loose ends are active objects from their first write; candidates and dispose let a project's own seat adopt or drop them, and an unjudged guess is searchable meanwhile.

Deployment and ergonomics

The service is PostgreSQL 16 with pg_trgm, Redis 7, an MCP server on port 8790 over streamable HTTP, and an arq worker; docker-compose.yml stands up the first two. Embeddings come from model2vec's potion-base-8M, a static lookup model run on CPU and stored as real[] with no vector extension. The first load reaches Hugging Face, and a failed load closes the semantic route while the lexical routes keep answering (src/orchestrator/semantics.py:1-25).

The repository's own .claude/settings.json wires prompt, tool and compaction hooks to absolute paths under the author's home directory, and .mcp.json points at a local server, so the committed hook set is the author's installation rather than a template.

4. Essential Implementation Paths

Assert. Actions.assert_property takes a transaction-scoped advisory lock on the object, property and source, reads the source's current row, and returns it with observed_at moved forward when value, confidence and class match (src/actions/core.py:229-289). Otherwise it inserts a row that supersedes the prior, flips the prior's is_current, writes an audit row only when the actor is not the source, and queues an outbox event (:290-333).

Merge, unmerge, status, rename. merge_objects (:641), unmerge_objects (:709), set_status (:818) and change_canonical (:848) each insert an object_events row, update the projection, write an audit row and queue an outbox event in one transaction. A rename appends the retired canonical to object_aliases; for a SoftwareProject, object creation resolves that alias to the migrated object instead of minting a twin (:134-147).

Search. The search tool runs _fn_search with the caller's agent id (src/mcp_server.py:1528-1550). An id-prefix route, strict full text, an OR-relaxed bag, trigram and the semantic route each require an active object, fuse by reciprocal rank, weight by grade and recency, drop other houses' reflections, and flag superseded decisions (src/orchestrator/compositions.py:384-560).

Housekeeping. retention_heartbeat deletes published outbox rows past 30 days and audit rows past 90 (src/workers/arq_worker.py:1234-1301). storage_housekeeping_heartbeat retires duplicate audit rows, deletes layout assertions, folds no-op re-assertions and moves week-old superseded history to the cold table, each step on a time budget (:1314-1411).

5. Memory Data Model

Objects of declared types, with properties as assertions and relations as links; every assertion and link carries a source, an evidence class, a confidence, an evidence URI and hash, and a case. A property's current view is one row per source, and the winner is chosen at read time by confidence and then observed_at, so disagreement between sources is visible rather than resolved on write.

Assertions live in two physical tables. Week-old superseded history moves from assertions_hot to assertions_cold by copy, verify and delete (src/orchestrator/migration_0064.py). observed_at is the time the claim was last confirmed: a repeated observation moves it on the existing row, and a fold carries the later time onto the surviving row (src/orchestrator/assertion_fold.py:7-19). Links carry first_seen, last_seen and valid_until. Nothing records the time a value began to hold apart from the time it was observed.

6. Retrieval Mechanics

One search engine with five routes. A hex token is looked up as an object id or canonical hash. Text runs as strict web-search syntax, relaxes to any-term when the strict form finds nothing, then falls back to trigram similarity. Beside these the semantic route cosines the query against an in-process vector cache. Routes fuse by reciprocal rank, and each hit carries the field, source, grade, time and snippet that matched (src/orchestrator/compositions.py:384-560). Every query lands in search_log with the routes that answered.

Grade weighs and does not gate. The SQL weight table maps self-declared to 1.0, authoritative API to 0.95, corroborated to 0.9, direct observation to 0.8, derived to 0.5 and anything else to 0.35 (compositions.py:230-233). That ordering differs from the evidence module's, where corroborated ranks first; no writer stores the corroborated class, so the branch is never taken.

trace_evidence, the provenance lens, returns one object's assertions, links and events in observed order, merged and retired objects included when named by id (compositions.py:1327).

7. Write Mechanics

The actions layer serialises a source's writes to one property with the advisory lock, so concurrent writers cannot fork a supersession chain. A bound Actions pins its pool to the transaction's own connection, so a helper inside the transaction cannot draw a second pooled connection while holding the first (src/actions/core.py:37-50).

The housekeeping deletions are deliberate and reasoned in their docstrings. Retention exists because the outbox and audit tables grew by tens of thousands of rows a day (src/orchestrator/retention.py:1-19). The fold deletes a superseded row only when it matches its predecessor on value, confidence, class, evidence URI, hash, case and helper run, and only when older than seven days (assertion_fold.py:7-19). Each runs as raw SQL against the pool rather than through the actions layer the header calls the only mutation path.

8. Agent Integration

The MCP server registers tools for search, provenance, dossiers, mail, seats, threads, decisions, merges, retirements and compositions. Claude Code hooks inject context on prompt submit, refuse most tool calls once the context passes a threshold until a settle lands, and write a handoff marker before compaction. A bridge under dsh-plugin/ mounts a DeepSeek Harness session. Screening flags three auto-run surfaces and a test conftest.py that executes on collection.

The agent's surface carries the verbs that move status: merge, unmerge, retire_object, retire_assertion and retire_link. Nothing an agent writes waits for a person.

9. Reliability, Safety, and Trust

The status filter is the reliable part. It is applied by every search route and by the vector index's maintenance, and a test asserts that an object leaving active is dropped from the index (tests/test_semantics.py:158-183).

The audit is two records with different lifetimes. object_events is untouched by any update or delete and records who moved an object's identity or status and why. audit_log covers the other actions for 90 days, and a source's own assertions are recorded in the assertions table instead.

The reflection boundary covers four reads. _hide_foreign_reflections runs on search and _visible_reflections on the provenance lens, select and the screen-focus tool (src/orchestrator/compositions.py:271-345, src/mcp_server.py:2254-2261). dossier returns every current property of any object it can resolve (src/orchestrator/dossier.py:127-132), and list_assertions returns any property's rows, with no house check. _fn_search and _fn_lap read their reader from args["caller"] before the context variable (compositions.py:403, :1350). composition(action='save') stores a spec as given, so a saved function call can name operator as its reader and see every house.

11. For Your Own Build

Steal

Grade the fact by how you got it and derive the number. A parser that writes 0.72 is guessing; one that writes "co-occurrence" is reporting, and the number becomes an ordering everyone downstream shares.

Put the lifecycle predicate in every route and in index maintenance. A filter in the SQL routes and not in the vector cache returns a merged object through the semantic route; deleting its vector closes that.

Make status transitions events with a required reason, and undo them with a compensating event that leaves the original in place.

Scope supersession to the source, so one source's correction cannot erase another source's disagreement.

Avoid

Stating "never mutated" over a table a housekeeping job prunes. The deletions here are argued in their docstrings; the module header and the README make the stronger claim, and the deletions bypass the one layer said to own every mutation.

A boundary that reads its subject from an argument. A reader identity a caller can supply, through any door, is a filter the caller sets.

A grade weight for a class nothing stores. The corroborated branch in search's weights reads as read-time corroboration and is never taken.

Fit

This suits one operator running a fleet of agents who should share work knowledge, where provenance and reversible identity changes matter and an audit horizon of 90 days is acceptable. Walk away if one agent's memory must be unreadable to another, if the audit trail must outlive a retention window, or if a weak claim must be kept out of the answer rather than ranked down.

12. Open Questions

Whether the 90-day audit window is meant to apply to merge and status audit rows, whose facts survive in object_events regardless.

Whether the reflection boundary is meant to cover dossier and list_assertions, and whether a saved composition is meant to set its own reader.

How the base confidences and search's separate grade weights were chosen; both are constants with an ordering and no stated derivation, and they disagree on where corroboration sits.
