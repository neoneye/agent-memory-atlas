On this page

1. Executive Summary

Otis is a local coding agent whose memory is three stores: an append-only session log, a Markdown fact store the agent writes with remember and reads with recall, and skills fetched from git. The fact store is small, legible and redacted; recall reaches every workspace's transcripts by design. The skills are the weak point: a skill is cloned from a URL with no revision recorded, in a codebase that checksums its own binary, its inference runtime, its model weights and its one bundled skill.

The fact store arrived on 27 September 2026 and follows a layout the code calls the Agent Memory Repo: a MEMORY.md index linking topic files, one fact per bullet, with the session it came from and the day. There are two scopes — a folder per workspace and one global folder — and only the two indexes enter the system prompt; the agent reads a topic, or searches facts and past sessions, through recall (src/memory/memory.ts:193, :310).

Recall crosses workspaces on purpose. Facts come from the asking workspace and the global scope, and up to eight transcript excerpts come from every workspace's sessions except the asking one. The test suite asserts it, and the README says the result goes to whichever model is answering, hosted or local (tests/memory/memory.test.ts:220-263, README.md:284-296).

The skills are unpinned. Installing one is git clone of the URL, with --branch <ref> when the URL names a /tree/<ref>/ folder; updating is git pull --ff-only. The manifest records id, url, path, installedAt, the skill list and a declared plugin identity, and no commit or hash (src/skills/manager.ts:126-132, :201, src/skills/catalog.ts:247-257).

The contrast is inside the same tree. The release archive is refused on a SHA-256 mismatch (src/cli/update.ts:158-161). The llama.cpp runtime archives carry 38 hard-coded digests and every GGUF file is verified before it is published into the cache. And the bundled documents skill is materialised into a directory named for a SHA-256 of its contents, with a modified cached resource refused (src/skills/bundled.ts:19, :61-67). The one skill the project ships is content-addressed; a skill a user installs is a moving branch. skills-lock.json carries a computedHash that appears once in the tree and that nothing reads.

2. Mental Model

Three durable surfaces, none of which holds a belief.

A session is a stream of events — prompts, responses, tool activity, usage, compaction — appended to one JSONL file per session. It is resumed whole, by id or by recency, and searched by word.

A fact is one Markdown bullet in a topic file, with optional [source: …; added: YYYY-MM-DD] metadata. It is born by remember (the agent's tool, the /memory command, the desktop settings page or an import of another agent's memory). It dies by forget, which deletes the line. There is no state between: a fact is live until it is removed, and nothing records that it was.

A skill is procedural memory with an install step. It is fetched, catalogued with any skill in .agents/skills or another agent's skill folder, and read on demand. The catalog entry is a name, a description, two paths, two invocation switches and a bundled flag, with no score or expiry (src/skills/catalog.ts:207-218).

Instructions are assembled per invocation from the home directory down to the working directory, nearest last, reading CLAUDE.md, GEMINI.md, Copilot or Cursor files where a folder has no AGENTS.md (src/core/context.ts:61-110).

Compaction is the one place something is decided about context, and it decides generously:

context reaches the threshold: min(250_000, window minus a reserve)
        │
        ▼
summary + kept suffix replace the messages in the model's context
        │
        └── session log appends { type: "compacted", summary,
                                  messages = kept suffix,
                                  turn = the in-flight segment, if mid-turn }
            earlier turn events are never rewritten

The model forgets and the store does not. The replaced turns stay on disk as the events that recorded them, and an in-turn checkpoint archives the active turn's segment in the event itself, so session search finds a word written before a compaction (src/storage/session.ts:144-182, tests/storage/session-search.test.ts:38-58).

3. Architecture

  • src/core/ — agent.ts runs the turn loop and places the memory indexes in the prompt (:299); compaction.ts holds the threshold and the cut; context.ts walks for instruction files.
  • src/memory/memory.ts — the fact store: remember, rememberAll, forget, listMemory, memoryIndex, recall, redactPrivate, and the optional git commit.
  • src/storage/ — session.ts, session-events.ts, session-index.ts (a per-file digest cache and the searchable texts), session-files.ts, session-lock.ts, workspace-registry.ts.
  • src/skills/ — manager.ts installs, updates and removes, with its manifest parser and lock; catalog.ts lists and serves resources; bundled.ts materialises the shipped skill.
  • src/app/other-agents.ts — lists and imports Claude Code, Codex and Gemini CLI instructions and memory.
  • src/tools/ — nineteen tools; recall, remember and forget are the memory-facing ones beside skill.
  • src/inference/, src/desktop/, src/cli/ — model runtimes, the Electron app, the terminal UI, the headless CLI and otis serve.

Deployment and ergonomics

A single binary from a release archive, a desktop app, or bun run from source. Inference can be fully local through a managed llama.cpp server, Ollama, LM Studio or any OpenAI-compatible server; hosted inference needs a provider key, and web search and page reading go to Parallel. No database, no service of the project's own. Every store is plain files a person can read and repair, and the fact store is Markdown a person can edit directly.

4. Essential Implementation Paths

The fact write — rememberAll (src/memory/memory.ts:240-261) collapses whitespace, runs redactPrivate, appends - text [source: …; added: …] to the topic file with appendFile, links the topic from MEMORY.md if absent, and calls commitMemory, which commits only when the memory folder itself holds a .git (:172-186).

The forget — forget (:264-302) scans every topic file, prefers an exact lower-cased match, falls back to substring, refuses unless exactly one line matches, and rewrites the file without it; an emptied topic file and its index link are removed.

The recall — recall (:310-339): searchNeedles(query, true) turns each word of three or more letters into a whole-word regex, facts are scored by how many needles hit topic + text, and searchAllSessions(query, { seeds: [cwd], words: true }) supplies transcript hits, filtered by hit.id !== session and cut to eight. The whole output passes redactPrivate.

The session partition — defaultSessionDirectory (src/storage/session-files.ts:16-24):

const hash = createHash("sha256").update(workspace).digest("hex").slice(0, 12)
return join(sessionRootDirectory(), `${slug || "workspace"}-${hash}`)

registerWorkspacePath writes workspace.json with the absolute path beside the sessions (src/storage/workspace-registry.ts:19-29).

The skill install — SkillManager.install (src/skills/manager.ts:88-175): git clone [--branch ref] -- repository dir, discovery, symlinks into ~/.agents/skills, and a manifest entry without a commit. The update (:177-268) resolves rev-parse HEAD into previousCommit, pulls, and uses previousCommit only for git reset --hard if a later step fails (:256).

The containment — readSkillResource (src/skills/catalog.ts:163-205): assertInside(skill.root, requested) before realpath, assertInside(root, canonical) after it, and TextDecoder("utf-8", { fatal: true }).

The checksums — src/cli/update.ts:158-161 for the release archive, src/inference/llama-runtime.ts:1008 for the runtime archive, src/inference/gguf-cache.ts:415 for weights, src/skills/bundled.ts:61-67 for the shipped skill.

5. Memory Data Model

A fact is { scope, topic, date?, text } parsed from a bullet by one regex, /^- (.+?)(?: \[((?:source|added): [^\]]*)\])?$/u (src/memory/memory.ts:31). source is the session id or the importing agent's id; added is the write day. There is no id, no status, no confidence and no validity interval. A hand-written bullet without metadata is a fact like any other.

The workspace memory folder is memory/ inside the workspace's session directory, so a fact's scope is where its file lives; the global folder is memory/ under the data directory (:82-101). Earlier single-file layouts — memory.md beside the sessions, and in 0.2.6 the project's .otis/memory.md — are migrated on first use and the old files deleted.

The session event union keeps { type: "compacted"; summary; messages; throughSeq?; promptId?; steeringCount?; turn? }, where messages is the kept suffix and turn the archived in-flight segment (src/storage/session-events.ts:91-99).

Files are private by construction — memory and session directories created 0o700, facts, indexes and session files written 0o600, the skill manifest written to a temporary path and renamed into place. A skill's origin is its source id and URL; which commit produced the text on disk is not recorded.

6. Retrieval Mechanics

Two indexes are always in context. memoryIndex reads each scope's MEMORY.md as it is on disk, and buildSystemPrompt places them in a <memory> block, each truncated at 32 KiB, with the instruction to read a topic through recall before relying on it (src/inference/system-prompt.ts:123-130). Hand-written lines in an index reach the prompt untouched, which the suite asserts (tests/memory/memory.test.ts:297-306).

Everything else is tool-mediated and lexical. A fact matches when any whole query word appears in its topic name or text, and facts with more matching words rank first; there is no embedding, no stemming and no recency. Session hits rank title matches above content matches, then by matched-word count, then by recency, with a snippet around the first hit (src/storage/session.ts:406-435). Tool outputs and compaction summaries are excluded from the searchable text (src/storage/session-index.ts:157-163).

The session half of recall reads every workspace directory under the data root (digestAllSessions, src/storage/session.ts:383), excluding only the asking session's id. The recall tool description says so: "excerpts from past sessions in every workspace". A project's transcripts are therefore retrievable from any other project, through redaction that removes credential shapes, emails and phone, card and national-id numbers and nothing else.

7. Write Mechanics

Writes are synchronous and model-free: no extractor decides what to keep, and no background pass consolidates. A fact is retrievable as soon as appendFile returns; a session event as soon as its line is synced.

The agent writes facts on its own initiative through remember, guided by a tool description that asks for one durable sentence about the project or the user's tooling and never about people. remember and forget are in RESTRICTED_BY_DEFAULT, and the interactive default mode is auto, under which a restricted tool is allowed without asking; ask prompts and dontAsk denies (src/permissions/policy.ts:12, :48-57, :83-84). The headless CLI defaults to dontAsk, so a headless run denies remember unless started with --auto.

--ephemeral refuses to create a session and cannot be combined with --session or --continue (src/cli/headless-cli.ts:395-396). It governs the session log only.

forget deletes the line and leaves no record of the value. The import page marks another agent's fact as imported by exact text match against live facts (src/app/other-agents.ts:45-74), so a fact forgotten in Otis is offered as new on the next import. When the memory folder is a git repository, the deleted line survives in that repository's history, which is the user's.

Session deletion is per session and total, artifacts first. A skill is corrected by pulling its remote, which is the same operation as being changed without asking.

8. Agent Integration

The agent is the product, so integration is the tool list and the permission layer. The memory-facing tools are recall (also available to subagents, src/core/agent.ts:115-123), remember, forget and skill.

Otis reads other agents' material in place when otherAgents is on, which is the default: skills from .claude/skills, .cursor/skills, .gemini/skills and .github/skills at every ancestor and at home, and those agents' instruction files where a folder has no AGENTS.md (src/skills/catalog.ts:16-45). Installed skills are activated as symlinks in the shared ~/.agents/skills folder, which the catalog's own comment says Codex also reads, so a skill installed through Otis is visible outside it. The desktop import copies Claude Code's per-project memory into the workspace scope and Codex's and Gemini CLI's into the global scope (src/app/other-agents.ts:94-122).

The README suggests cloning a shared memory repository into a memory folder's place. Its MEMORY.md then enters the system prompt as written, from whatever that remote held when it was cloned.

9. Reliability, Safety, and Trust

The unpinned skill is the finding. A skill is instructions the model reads and follows. Installing takes the default branch or a named ref, update takes whatever that branch holds at the time, and the manifest has nowhere to record what was reviewed. The project's own bundled.ts is the worked example of the alternative: the cache directory is named for a SHA-256 of the skill's contents and a modified resource is refused. Recording the resolved commit at install and showing a diff on update would close the gap; #updateSource resolves that commit for rollback and discards it.

Recall is a cross-project read. Workspace facts stay in their workspace, but transcript excerpts do not, and the read is not behind a permission: the recall tool is unrestricted. Redaction is a fixed list of shapes, so a project-specific secret that matches none of them reaches another project's context and, with a hosted model, the provider.

The fact store has no doubt state. A wrong fact is live until it is forgotten, and a forgotten one leaves nothing that would stop it being remembered again. The prompt's precedence rule — the repository and the user's instructions win — is advice to the model, not a filter.

The care elsewhere is real. -- before a URL and a refusal of URLs starting with -, --ff-only, a scrubbed child environment, containment on both sides of realpath, a fatal UTF-8 decode, .. and absolute-path rejection in the manifest parser, atomic manifest writes, and a PID-plus-token lock that treats a partial lock file as live for 30 seconds.

Compaction does not destroy evidence, because the log is never rewritten.

A move resets the workspace view. The session directory hashes the absolute path, so after a move --continue and workspace facts start empty. workspace.json records the old path, and the desktop's global history lists the old sessions, so the material is findable from there and through recall; the workspace facts are not.

11. For Your Own Build

Steal

  • Never rewrite the session log, and archive the in-flight segment at a mid-turn checkpoint. The context shrinks and the record does not.
  • Index in the prompt, bodies on demand. Two short MEMORY.md files cost a few lines per turn, and the model fetches a topic when it needs it.
  • Redact on both sides. remember redacts before writing and recall redacts before returning, so a secret that reached a transcript does not come back through memory in a credential shape.
  • Content-address what you ship. A cache directory named for the hash of its contents, and a refusal when a cached file differs, is a few lines.
  • Assert containment on both sides of realpath.

Avoid

  • Procedural memory pinned to a URL. Record the revision that was reviewed.
  • A hash field nothing computes. computedHash in skills-lock.json reads as an integrity check and is read by nothing.
  • A cross-project read with no permission gate. If recall must span projects, make the span an argument the user grants, not the default.
  • Deletion that forgets it happened when an import or a model can write the same value again.

Fit

Right for someone who wants a local coding agent on open weights with readable history and a fact store they can edit in a text editor. Wrong as a memory system to lift for anything multi-project or shared: workspace isolation is a directory, the transcript half of recall ignores it, and there is no correction state. Adopt the skill manager only with a revision field added.

12. Open Questions

  • Was skills-lock.json once enforced? It carries a sourceType and a computedHash the runtime manifest has no concept of; whether it is a development record or a lapsed check was not determined.
  • What does update do for a skill installed at a tag? --branch <tag> leaves a detached checkout, where git pull --ff-only should fail; the manager's message for that case was not traced.
  • How often does the agent call remember unprompted? The session logs record every call; the rate was not measured for this reading.
  • Is cross-workspace recall wanted by users of shared machines? The desktop settings expose memory editing but no switch for the session half of recall.
