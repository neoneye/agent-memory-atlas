On this page

1. Executive Summary

Verimem is a SQLite memory for agents whose writes pass an admission gate with a local judge model, whose recall SQL withholds three stored statuses, and whose hash-chained mutation log refuses to remember what it deleted. It also keeps an event time beside the record time and reads both. The weak side is the agent's own tool surface: two MCP write doors mint facts with no writer label, so the rule that a writer cannot release its own quarantine does not reach them, and scope is an argument the agent may leave out.

It describes itself as "[v]erified memory for AI agents", in Python, dual-licensed AGPL-3.0 with a paid commercial option, with versions 0.3.x and earlier released under MIT. Its promise is a conjunction:

"Every write passes an admission gate, every read carries provenance, and a claim the source openly contradicts does not come back as truth."

The mechanism worth carrying away is what the audit log refuses to store. Most projects that reach for a tamper-evident chain put the content in it, and then discover that an immutable record of what was deleted is itself a copy of what was deleted. mutation_audit.py argues the other way:

"ACTION-ONLY, never content (F1/F8): storing WHAT was deleted — even as a hash, brute-forceable on short text — inside an immutable chain makes GDPR Art.17 erasure a logical contradiction. The chain proves THAT/WHO/WHEN/ WHICH-RECORD, not what the record said."

Every destructive operation — delete, purge, forget, supersede, reset — appends one row "INSIDE THE SAME TRANSACTION as the mutation itself", and record_mutation "never swallows", so a failure to record propagates instead of leaving an unrecorded deletion. Both decisions are attributed to "two independent adversarial reviews (GLM-5.2 + deepseek, convergent findings)", with the finding ids each one answers.

The status vocabulary withholds rather than ranks. The store accepts a closed set — verified, model_claim, provisional, legacy_unverified, orphaned, quarantined, user_belief — and the curated view carries status NOT IN ('orphaned', 'quarantined', 'user_belief'). Every route back to the withheld material is a named opt-in on recall: include_superseded, include_orphaned, include_beliefs, min_status. The session-start banner and the proactive briefing apply the same three exclusions before they put recent facts into a prompt, and committed tests assert the exclusion on a populated store with a positive control beside it.

Time has two axes. The schema documents asserted_at as the event time, when the fact was said or was true, and sets it apart from created_at, the transaction time at which the store learned it. Callers supply it, and NULL means unknown rather than the write clock. recall_as_of returns what was asserted by an instant and not yet superseded by it, which answers "what did we believe then about then".

The route out of quarantine checks a label, and two write doors carry none. SemanticMemory.libera_dalla_quarantena refuses when the requesting principal equals the stored writer_principal, and the MCP server stamps mcp:unbound on its main writes and on every restore request, so a fact written through hippo_remember cannot be released through hippo_quarantine_restore. The code comments credit the rule to this atlas ("Atlas, 29/09"). The refusal runs only when both labels are non-empty (verimem/semantic.py:5826). hippo_transcript_promote and hippo_ingest_conversation build their facts without a writer label, both can store a fact as quarantined, and the restore tool then releases it to the agent that wrote it. The README states the other limit itself: "These are labels, not authenticated identities." Four marks: trust_state, bitemporal, audit_log, negative_eval.

The project corrects its own documentation in public. The README's first box carries a correction, the version the old claim was true of, the function that was reachable only from warmup, the test that "records the measurement and the fix", and the admission that matters: "The fix shipped; the text did not follow it. Corrected here."

2. Mental Model

A fact is a proposition with a status, and the status decides whether an agent is handed it.

A status is a stored verdict. orphaned, quarantined and user_belief keep a fact out of recall and out of both context assemblers.

A widening is a named keyword the caller had to type.

A quarantine is reversible, and only quarantine is: a restore refuses an orphaned or superseded row.

A release is refused to the principal the store recorded as the writer, and granted when the store recorded none.

An event time is when the fact was said or true; the record time is when the store learned it; a supersession retires a fact in record time.

An audit row proves that a deletion happened and cannot tell you what was deleted.

Deployment and ergonomics

Everything runs locally on SQLite. The first gated write fetches the judge model — 711 MB by the README's figure — and the README measures a cold first call at 85.7 seconds before explaining how to move that cost to verimem warmup. A shared daemon can hold the judge for several writers; without it a CLI write is "judged in process in ~22 s", the README's own measurement with the model installed. No API key is needed to store a fact. The MCP server is registered as io.github.aureliocpr-ctrl/verimem and launched with uvx; the gateway is a FastAPI app served by verimem gateway serve, binding loopback by default.

5. Memory Data Model

A fact carries a proposition, a status from the closed vocabulary, a writer role and a writer_principal, grounding evidence (grounding_score and grounding_span), a confidence tier, and three times: created_at for when the store learned it, asserted_at for when it was said or true, and an optional valid_until. A retirement sets superseded_by and superseded_at. Episodes carry task traces, skills and outcomes beside the facts.

The writer label is stamped by the surface, never read from tool arguments: the MCP server's comment calls a client-supplied value "a spoof attempt". The SDK stamps sdk:local, the CLI cli:local plus an optional VERIMEM_ACTOR suffix, and MCP mcp:unbound. Facts that the transcript-promotion and conversation-ingest paths build carry no label.

Ids differ by door. MCP's hippo_remember derives the id from a hash of the proposition and topic, and the upsert leaves superseded_by untouched, so an identical re-assertion lands on the retired row. The SDK and the extraction paths mint random ids.

6. Retrieval Mechanics

BM25 and semantic recall over the curated view, with the status filter compiled into both the appended predicate and a standalone filter string so the two cannot drift. The cold-encode fallback delegates to search_facts and forwards the opt-ins. A set of analysis and cleanup tools reads list_facts() without the filter on purpose; the briefing passes hide_low_trust=True.

search_facts(as_of=...) puts COALESCE(asserted_at, created_at) <= ? into the SQL and counts how many rows that excluded, and recall_as_of keeps the facts asserted by the instant and not yet superseded by it. The SDK's search defaults as_of="auto", routing a query with a retrospective anchor to the time-travel path.

Scope is applied when asked for. hippo_facts_recall, hippo_facts_search and hippo_facts_list read user_id, agent_id and run_id from the tool arguments, narrow by topic LIKE '<prefix>%' and post-filter with matches_scope. Without those arguments the read is unscoped, and a docstring in the server says a multi-tenant deployment "must NOT treat scope as a hard security boundary". The session-start banner reads the eight most recent facts with the status filter and no scope predicate.

7. Write Mechanics

validate="fast" is the default tier: pure substring detectors, "cold execution << 1 ms". full adds claim validation against the agent's semantic memory at a measured mean of about 13 ms. off exists and is labelled what it is — "[p]ure escape hatch for migrations, replays, deliberate writes." Behind the detectors a local NLI judge scores the claim against the supplied source; a write it does not support is stored quarantined rather than dropped, and the receipt says which layer held it and why.

The write path is synchronous. Conversation ingest extracts atomic facts with the agent's own LLM and judges each one against the dialogue; transcript promotion judges an agent-supplied proposition against the verbatim turn.

8. Agent Integration

A CLI, an MCP server exposing every tool unless ENGRAM_MCP_TOOLS_PREFIX narrows it, an SDK client, a REST gateway whose module docstring derives the tenant from the presented key and never from a request field, Docker compose files, a Claude Code plugin manifest and hook bundles. The gateway's restore route, the SDK's Memory.restore and the bulk verimem facts requalify-quarantined --apply carry no writer comparison; the commit that added the rule says the SDK and HTTP restores "stay outside this request".

9. Reliability, Safety, and Trust

The strong parts are the fail-closed audit, the withholding statuses applied to every read that feeds a prompt, the reversible-but-narrow restore, and a documentation habit that publishes corrections and limits rather than quietly fixing them.

The weak parts sit on the agent's own surface. The writer-label rule covers the MCP writes that stamp a label and none of the ones that do not, so the quarantine an agent's transcript promotion or conversation ingest produces is a quarantine the same agent can lift. Scope is an optional argument. A single release from quarantine leaves the audit chain untouched: restore_fact emits observability and flow events, while the bulk requalify path records a restore row. Nothing is keyed on a rejected value.

11. For Your Own Build

Steal

Decide what your audit chain is allowed to contain before you build it. An immutable record of content is a second copy you cannot delete, and the argument in mutation_audit.py states that trade in four lines.

Write the audit row inside the mutation's transaction and let a failure propagate. An audit that can fail silently is wrong exactly when it matters.

Name every widening. A recall signature where include_orphaned has to be typed is one where the default is defensible and the exception is visible in the caller's code. Apply the same filter to whatever assembles context at session start.

Keep event time in its own nullable column and let NULL mean unknown. The schema comment records why: storing the event time in created_at hid most of a back-dated store from recall.

Avoid

A self-release rule that compares two labels and passes when one is missing. Every door that writes has to stamp the label, or the rule needs to refuse when the writer is unknown.

Fit

A single-operator deployment that wants to know why it believes something, and can keep the agent's MCP surface narrowed with ENGRAM_MCP_TOOLS_PREFIX. Not a multi-tenant library where the tenant boundary has to hold against the caller.

12. Open Questions

Whether the release rule should refuse an unlabelled writer, or the promotion and ingest paths should stamp the surface label as hippo_remember does.

Whether scope should move into the store. Everything else here is enforced where it cannot be forgotten; scope depends on the caller passing it, and the session-start banner does not.
