On this page

1. Executive Summary

Vestige is a local MCP memory for coding agents in which every mutation is proposed, judged by a deterministic gate, and admitted as a frame on Strata, an append-only log whose frames are hash-chained and whose sealed segments are signed. State is replayed from the log rather than stored beside it, which makes the audit trail structural rather than a table someone remembered to write. The weak side is review: the Memory PR queue that would hold a risky write for a person is forced to its pass-through mode on the only backend the binary ships.

Every write has one path. admit_write_with_params (crates/strata-store/src/store.rs:1596-1668) appends a PROPOSE frame and a GATE frame, refuses on Deny or Hold with both frames left on the log, then appends an EFFECT citing the payload digest, and only then the single STORE_WRITE frame at :1664. Ingest, edit, retire, review, edges, anchors, intentions and salience changes are all StoreOp variants through that function. receipt get explains a write, receipt replay re-derives it and reports a mismatch, and vestige strata-verify checks the chain and the trailers offline.

Erasure is refused and says why. purge, delete and delete_knowledge return unavailable_in_4_0 (crates/vestige-mcp/src/server.rs:387-394). suppress hides a record from every read and keeps its bytes, and its tool description says it "cannot be undone … and is not erasure" (server.rs:594). A committed test scans the raw segment files for the suppressed marker and fails if the bytes are gone, with the message "suppress must not claim erasure" (strata_memory.rs:4583-4592).

The project removed its own retrieval. Version 4.0 (30 September 2026) dropped embeddings, keyword search and SQLite from the default build. The agent's recall resolves an exact id, a unique prefix of eight or more characters, or an exact tag, and a free-text query returns handle_required with candidates. The one ranked read is the lifecycle-hook packet, which runs exact-token BM25 over the scoped store (tools/memory_packet.rs:380). The Fellegi-Sunter merge and supersede planner is withheld on Strata (server.rs:396-420), and its scorer score_pair has no caller outside its own file.

The benchmark page labels its own numbers as describing another engine. docs/BENCHMARKS.md opens by saying "There is no 4.x benchmark on this page." Section 10 has the rest.

2. Mental Model

A memory is a NodeRecord (crates/strata-store/src/types.rs:101-133): id, scope, content, sorted tags, node type, created_at_ms, valid_from_ms, valid_until_ms, an optional superseded_by, and source provenance. Its FSRS card lives in the kernel state, folded from review events on the log. Retrievability is derived on read from the card and the clock, and docs/STORAGE.md states that it is not stored.

Nothing on the log is overwritten. An edit admits a successor and retires the predecessor. A suppression admits a one-character anchor node, retires the target in its favour, then retires the anchor (crates/vestige-mcp/src/strata_memory.rs:854-895). An undo appends a compensating record. A record is live while superseded_by is empty, and that is the only lifecycle test any read applies (strata_memory.rs:1613).

A retirement is a RETIRE proposal, and the pinned policy decides it by name. default_policy (store.rs:516-541) allows four named rules — edit only when the successor was admitted in the same tool call, suppress, intentions, and purge only with confirm — holds every other RETIRE, and allows any other write under a blast-radius cap of 10,000. The rule name travels as a domain-separated hash in the proposal's params_hash, never as content.

3. Architecture

Ten crates. strata is the log engine: segments, group commit, sealing and tail verification (crates/strata/src/log.rs). strata-gate is the policy VM and the record kinds PROPOSE, GATE, EFFECT, GAP, LESSON_ALARM, CANARY and ALERT (crates/strata-gate/src/record.rs). strata-store is the memory registry folded from the log, and strata-kernel the integer FSRS fold. strata-migrate and vestige-upgrade import a v3 vestige.db read-only into a new log under a signed migration receipt, and strata-verify checks a data directory offline. vestige-core keeps the cognitive modules; vestige-mcp is the server, the CLI, the dashboard and the hook surface.

The log format is in crates/strata/src/format.rs:12-14 and :43-44. Each frame carries the blake3 of the previous frame, a segment header carries the previous segment's hash, and a sealed segment ends in a trailer holding the frame count, a Merkle root, and an Ed25519 signature over the segment id, the previous segment hash and that root. Persisted records carry integers and strings only, and the store reads no wall clock (types.rs:1-7), so replay is deterministic.

There is no SQLite backend to fall back to. legacy-sqlite = [] is an empty feature in both crates/vestige-core/Cargo.toml:17 and crates/vestige-mcp/Cargo.toml:17, and crates/vestige-core/src/storage/ holds contracts and types with no SQL implementation.

4. Essential Implementation Paths

Save — remember (tools/remember_unified.rs) → smart_ingest, which parses validFrom/validUntil, infers one unambiguous as of YYYY-MM-DD phrase (tools/smart_ingest.rs:388), and checks the secret gate and canonical duplicates → ingest_in_scope_with_receipt (store.rs:1721-1760) → declared links through check_links, which refuses a target in another scope (strata_memory.rs:1003-1035) → salience backfill for the new id.

Prompt hook — packages/vestige-init/hooks/memory.cjs extracts facts from the user's prompt by pattern into a per-session queue file, saves up to 20 at turn end through remember, and on session, prompt and tool events calls session with memory_hook, which lands in memory_packet::packet (tools/session_context.rs:127-133).

Recall — recall::handle_flow (tools/recall.rs:243-321) → resolve_handle (strata_memory.rs:1942-2018): exact id, then a unique prefix of eight or more characters, then an exact case-sensitive tag, each over live records only.

Retire — curate edit → StrataStore::edit; curate suppress → suppress_memory (strata_memory.rs:3717-3746), which also retires every live GhostLink composition naming the record.

Undo — dedup action undo with an operation_id and confirm=true appends a compensating record; strata_memory.rs:5176-5215 is the test.

The variants are borsh-positional, and the file says to append only, "or old logs stop replaying" (op.rs:66-67).

The edge vocabulary calls supersedes and corrects "review-gated" trails (types.rs:36-38). corrects has no writer outside the v3 importer. supersedes is a declared link the caller adds on save, and it records an edge without retiring the target (strata_memory.rs:935-997, :1040-1083).

6. Retrieval Mechanics

Recall is lookup, not search. resolve_handle filters with retrievable and nothing else. It reads no scope and no validity window, so a tag returns every live record carrying it from every scope, expired ones included. A Strata-side description string advertises "exact-token BM25 over stored text" for recall (server.rs:600); the recall code path runs no ranking, and lexical::rank has one caller, the hook packet.

The hook packet is the ranked read. packet (tools/memory_packet.rs:344-530) loads the scope's nodes, drops retired ones and those outside their validity window at the current time, and ranks the prompt by exact-token BM25 over content and tags (tools/lexical.rs:88-140). A prompt naming one recorded person does not pull in another person's records. Up to four two-hop bridges follow person:, place:, food:, file:, service: and symbol: tags, and whole records are packed into about 3,000 tokens. An empty prompt injects nothing.

Walks follow recorded edges only. causal_walk and the graph subgraph skip superseded endpoints (strata_memory.rs:2461-2480), and GhostLink proposals stay inside one scope (crates/strata-store/src/ghostlink_tests.rs:309).

Scope is a predicate on some reads and absent from the main one. The hook packet filters on scope at memory_packet.rs:350, but the hook passes none, so session_context.rs:128 defaults it to user. A record the agent saves under a project scope is never injected, and any tag recall returns it. The documentation states the cross-scope behaviour as intended: "Exact-handle reads such as an id or a prefix work across scopes" (docs/STORAGE.md).

7. Write Mechanics

The gate is deterministic: an ordered rule list, first match wins, default deny, no clocks, floats or environment (crates/strata-gate/src/policy.rs:1-2). A secret gate runs before it; docs/STORAGE.md lists the live-key families it refuses in every stored field.

Writes arrive from the user's prompts as well as from the agent. explicitFact in memory.cjs matches possessions, people, places, dates, jobs, health and preferences, and tags them person:, place:, preference:key=value and similar. A queued fact is saved at the next turn event with an intent_id hashed from client, session and prompt, so a replay returns the first write instead of making a second one.

Every save triggers backfill. remember runs the retroactive salience planner on each new id (tools/remember_unified.rs:140-167). It walks recorded edges backward and raises the stability of older memories sharing an exact entity. Each change is an AdjustSalience frame carrying the exact before-score, so undo restores it, and dry_run previews with nothing appended (tools/backfill.rs:16-27).

A save tagged pinned rewrites the agent's instruction file. After the ingest, remember calls project with path: "CLAUDE.md" and confirm: true supplied by the code itself (tools/remember_unified.rs:188-205). project replaces only the fenced region, inside the server's working directory, from the user scope's durable records.

Duplicates are exact. The canonical index keys on (scope, canonical_hash(content)), and a duplicate becomes an echo node pointing at the original (store.rs:1262-1290).

8. Agent Integration

Six advertised MCP verbs — session, remember, recall, causal_walk, curate, precedent (server.rs:28-35, :1231-1330) — plus a reflex tool left out of tools/list for hooks to call. Older tool names dispatch too, and each such call appends an unsigned line to legacy-tool-calls.jsonl (server.rs:37-68).

@vestige/init installs the hooks. Besides the memory hook, Reflex keeps per-session context manifests and pushes each retirement of a held memory once to every other session holding it (tools/reflex.rs:979-984; test at :4053). At compaction it gives back the memories a summary dropped, under the test at :4179.

The Operator gates in operator/ and operator-lite/ judge shell and tool calls before they run. They write receipts and permits, which the precedent verb reads and Reflex turns into stop memories. They are not on the memory write path.

9. Reliability, Safety, and Trust

Bitemporal — awarded. valid_from_ms and valid_until_ms are separate fields from created_at_ms (types.rs:122-126). The MCP adapter stamps created_at_ms from the wall clock and takes validity from the caller (strata_memory.rs:1534-1536). The agent sets it through remember's validFrom/validUntil (smart_ingest.rs:81-87), an inferred as of date, or the 30-day default on state records. The hook packet and the projection withhold a record outside its window. No Strata read asks for a past instant: recall's validAt belongs to the legacy reason mode, which returns similarity_disabled.

Audit log — awarded. Every mutation is a frame behind a recorded gate verdict, and the log is the store. The intent index and maintenance stamps are side files, and neither changes what a read returns.

Negative eval — awarded. retired_nodes_stay_out_of_every_read_tool (strata_memory.rs:4735-5149) retires a marker record linked to a kept control, asserts the control is visible, then asserts the marker's content and id are absent from every agent read tool. That is the paired shape a filter excluding everything cannot pass. The hook packet has no such case.

Human review — withheld; a queue nothing fills. trace/review.rs defines Memory PRs: fast, risk_gated and paranoid modes, a risk taxonomy, and dashboard routes to list and decide them (dashboard/mod.rs:225-236). The server calls the gate before a mutating tool runs and after a write lands (server.rs:1571, :1734). read_review_mode returns Fast whenever the backend is Strata (trace_recorder.rs:118-137), and Strata is the only backend. The gate VM's require_human modifier turns an allow into a permanent Hold (policy.rs:35-38, :78-80), and no shipped rule sets it. What remains are caller-set flags, confirm=true on undo and on project write; suppress needs none.

Trust state — withheld. The axes are lifecycle (superseded_by), validity, scope, FSRS retrievability, a float trust on receipts, and actor endorsements whose weights, in actor.rs:13-15's words, never establish that a claim is true. None is a credence state that withholds a record.

Tombstone — withheld. A retired record gives up its place in the canonical index (store.rs:1265-1277), and find_node_by_canonical_hash returns live records only (:1769-1779). The same content saved again is a fresh live record, and the prompt hook saves it again whenever the user repeats it.

Scope enforced — withheld. The scope key reaches the hook packet, the projection and GhostLink, but not recall, the agent's read verb. That is the line drawn for Cortex: a predicate half the read paths cannot express does not hold the mark.

The CauseBench retraction stands, as does the Answer Accuracy versus Conflict Recognition Score correction that puts the best CRS at 0.2501. The Silent Rotation table carries its own caveat: only the rag, mem0 and zep baselines converged on the wrong key.

11. For Your Own Build

Steal

  • Make the log the store. One function appends propose, verdict, effect and data in that order, and state is a replay. Nothing can mutate memory without leaving the frame that explains it.
  • Name the retirement rule, and hold the unnamed. Four named RETIRE rules are allowed and every other retirement is held, so a new retirement path fails closed until someone writes its rule.
  • Withhold an action rather than fake it. Erasure, merge planning and protect are dropped from the advertised schema and refused with a reason, and scan reports mergeCandidates as unavailable so it cannot be read as "none found".
  • Test the absence beside the presence. The retired-read test keeps a linked control and asserts both halves for every tool.
  • Store the exact before-value with every score change. AdjustSalience carries the old stability and the latest card event, so an undo is exact.
  • Tell other sessions when a belief they hold is retired. The push reaches every session holding the old id, once.

Avoid

  • A review mode that falls back silently. A configured paranoid mode becomes fast with one log warning, and the dashboard keeps serving the queue's routes.
  • A memory verb that writes the agent's instructions. A pinned tag rewrites CLAUDE.md with a confirmation the code supplies.
  • A scope that only one read honours. The hook partitions; recall does not.
  • Suppression without a value key. A hidden fact comes back the next time the user says it.
  • A tool description that outruns the code. One recall description says BM25, and the code resolves handles.

Fit

For one developer who wants an agent's memory, and its corrections, to be provable after the fact, and who will work by exact ids and tags rather than by search. Not for anyone who needs erasure: the log keeps every byte, and the documentation says to use full-disk encryption and points to planned crypto-erasure.

12. Open Questions

  • Does any shipped path produce a held RETIRE? Every unnamed retirement is held and nothing releases it; no path past the four named rules was traced.
  • Is the stale-belief list persisted across restarts? The retirements live in Reflex state, and whether that state survives a restart was not traced.
  • Does any read consult the anchor verdicts? RecordAnchorVerdict caches verified, moved, drifted, missing or unverifiable, and the op comment says readers re-verify against the live tree.
