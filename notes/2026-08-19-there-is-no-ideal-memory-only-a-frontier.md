# There is no ideal memory, only a frontier

**Status:** decision, with the argument kept because the question will return.
**Origin:** *"would it make sense describing the ideal memory for AI.. I imagine
continuous learning, that never forgets stuff, and performs max on all KPIs."*

## Why the page was not written that way

Each third of that sentence is refuted by the corpus, which is what made the
answer easy to ground and worth keeping.

**"Never forgets" is the atlas's most-documented failure, not its ideal.**
Reflexion retracts nothing and grows unboundedly behind a fixed three-item read
window. Voyager concatenates skills into the prompt with no failure memory.
gh-aw versions repo memory in git and *"nothing is ever marked wrong"*. Helix
AGI's journal — which its own docstring calls the single source of truth — hears
about no deletion, so a removed belief resolves back out of the log into the
prompt through a dangling pointer. A store that never forgets is a store in
which nothing can be unsaid.

**"Max on all KPIs" is incoherent, and one system proves it deliberately.**
Engram Alpha commits a whole tradeoff curve — a score floor and a knee cut —
and fits its abstention line *per graph* from unanswerable probes built out of
that graph's own vocabulary. Nobody fits an abstention line if abstention is
free. Its report still names the price it does not pay: how often an answerable
question gets warned.

**"Continuous learning" has a failure mode two systems found and cut.** Engram
Alpha stamps `last_seen` on retrieval *for observability only*, because exposure
would otherwise let a broad recurring query certify its own outputs. Helix AGI
removed relation count from a belief's mass under a comment naming the loop:
*"relations → mass ↑ → gravity ↑ → co-injection → more relations"*. A system
that learns continuously from its own use trains on its own errors.

## The second argument, which matters more

An ideal-memory page would fight `/build/`. That page opens with *start from the
failure you cannot tolerate, not from the mechanism that sounds most rigorous*,
and says plainly that the correctable stack is not the default. A page
describing the maximum invites exactly the over-building those pages exist to
prevent — and sharpens the criticism an outside review already made, that the
atlas makes every missing mechanism feel like a moral failure.

## What was written instead

[What you buy, and what it costs](../content/tensions.md): six axes with systems
at both ends and what the choice forced them to build. Recall against
abstention, retention against correctability, scope against reuse, synchronous
writes against write-to-readable lag, audit completeness against growth,
reinforcement against truth.

Two decisions inside it worth keeping:

- **It closes with what is *not* a tradeoff** — scope as a schema key before
  there is an index, raw evidence retained before the model is called, recall
  fenced as data, the embedding model stamped beside the embedding. Without that
  section the page reads as an argument for building nothing, which would be the
  opposite of useful.
- **The six axes are an editorial judgement, not a derivation.** The page does
  not claim completeness, and if it is ever held to the rubric's standard that
  should be stated in a line.

## The transferable form of the answer

When asked for the maximum of a set of properties, check whether the corpus
shows them trading. If it does, the honest deliverable is the frontier and the
evidence for each axis — not a specification nothing can satisfy, and not a
refusal.
